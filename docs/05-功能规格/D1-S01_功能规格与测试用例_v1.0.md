## 1. 功能规格概述

### 1.1 功能范围

D1-S01 货品主数据管理模块提供以下核心能力：

| 能力 | 描述 | 优先级 |
|------|------|--------|
| 货品CRUD | 创建/查看/修改/删除货品主数据 | P0 |
| 分页列表 | 支持分页、关键词搜索、分类/状态筛选 | P0 |
| 统计概览 | 货品总数/激活数/锁定数/分类分布 | P0 |
| 锁定保护 | 锁定后关键字段不可直接修改 | P0 |
| 变更申请 | 关键字段修改需走审批流程 | P1 |
| 种子数据初始化 | 一键加载展会演示数据 (23 SKU) | P0 |

### 1.2 非功能需求

| 指标 | 要求 | 测试方法 |
|------|------|----------|
| API响应时间 | P50 < 200ms, P99 < 500ms | 性能测试 |
| 并发支持 | 单用户（Edge UI场景） | N/A |
| 数据持久化 | JSON文件，操作后立即保存 | 文件检查 |
| 认证安全 | 所有端点L2 PIN保护 | 未认证访问测试 |

### 2.14 T14: 变更申请提交 ⚠️ Known Issue

| 属性 | 值 |
|------|-----|
| **用例编号** | T14 |
| **用例名称** | 提交货品变更申请单 |
| **优先级** | P1 |
| **前置条件** | 存在 active 状态的货品 |
| **测试类型** | 正常流程 |
| **当前状态** | ❌ Fail (model校验问题) |

**测试步骤**:

```
1. POST /api/v1/products/FP-MW-001/change
   Body: {
     "change_type": "price_adjust",
     "old_value": {"unit_price": 128.0},    // Dict格式
     "new_value": {"unit_price": 135.0},    // Dict格式
     "reason": "供应商通知涨价5.5%"
   }
2. 预期: 响应状态码 = 201, 返回 ChangeRequest 对象
3. 实际: 422 Unprocessable Entity (model校验失败)
```

**问题根因**:
- ChangeRequest 的 old_value/new_value 字段定义为 `Dict[str, Any]`
- 但某些情况下传标量值导致校验失败

**修复方案**:
- 调整 API 层的请求验证逻辑
- 或在前端构造正确的 Dict 格式

**计划修复**: D1-S02 开发前

### 2.15 T15: 变更申请列表 ⚠️ Known Issue

| 属性 | 值 |
|------|-----|
| **用例编号** | T15 |
| **用例名称** | 查询变更申请列表 |
| **优先级** | P1 |
| **前置条件** | 有变更申请记录 |
| **测试类型** | 正常流程 |
| **当前状态** | ❌ Fail (路由顺序问题) |

**测试步骤**:

```
1. GET /api/v1/products/changes
2. 预期: 返回变更申请列表
3. 实际: 被 /{sku_code} 路由匹配，返回404 ("SKU 不存在: changes")
```

**问题根因**:
- FastAPI 路由按定义顺序匹配
- `/products/{sku_code}` 定义在 `/products/changes` 之前
- "changes" 被当作 sku_code 参数

**修复方案**:
- 将 `/changes` 路由移到 `/{sku_code}` 之前定义
- 或使用 `router.add_api_route()` 显式控制路由顺序

**计划修复**: D1-S02 开发前

## 4. 自动化测试脚本

以下 Bash 脚本可用于回归测试：

```bash
#!/bin/bash
# D1-S01 回归测试脚本
# 用法: bash d1-s01-test.sh [edge-ui-host]

HOST="${1:-127.0.0.1:9080}"
COOKIE="/tmp/edge_test_cookies.txt"
PASS=0
FAIL=0

red() { echo "\033[31m$1\033[0m"; }
green() { echo "\033[32m$1\033[0m"; }

check() {
  local desc="$1" expected="$2" actual="$3"
  if [ "$actual" = "$expected" ]; then
    green "✅ $desc"
    PASS=$((PASS+1))
  else
    red "❌ $desc (expected: $expected, actual: $actual)"
    FAIL=$((FAIL+1))
  fi
}

echo "=== D1-S01 回归测试 ==="
echo "Host: $HOST"

# T01: 登录
echo "--- T01: Login ---"
curl -s -c "$COOKIE" -X POST "http://$HOST/api/v1/auth/login" \
  -H "Content-Type: application/json" -d '{"pin":"123456"}' > /dev/null
check "Login" "0" "$?"

# T02: 统计
echo "--- T02: Stats ---"
STATS=$(curl -s -b "$COOKIE" "http://$HOST/api/v1/products/stats")
echo "$STATS" | python3 -c "import sys,json; d=json.load(sys.stdin); exit(0 if d.get('total_categories')==6 else 1)" 2>/dev/null
check "Stats has 6 categories" "0" "$?"

# T04: 列表
echo "--- T04: List ---"
LIST=$(curl -s -b "$COOKIE" "http://$HOST/api/v1/products?page=1&page_size=5")
echo "$LIST" | python3 -c "import sys,json; d=json.load(sys.stdin); exit(0 if len(d.get('items',[]))<=5 else 1)" 2>/dev/null
check "List pagination works" "0" "$?"

# T06: 详情
echo "--- T06: Detail ---"
DETAIL=$(curl -s -b "$COOKIE" -o /dev/null -w "%{http_code}" "http://$HOST/api/v1/products/FP-MW-008")
check "Detail existing SKU" "200" "$DETAIL"
NOTFOUND=$(curl -s -b "$COOKIE" -o /dev/null -w "%{http_code}" "http://$HOST/api/v1/products/NON-EXIST")
check "Detail non-existent SKU" "404" "$NOTFOUND"

# T13: 前端页面
echo "--- T13: Frontend ---"
PAGE=$(curl -s -o /dev/null -w "%{http_code}" "http://$HOST/products.html")
check "Frontend page accessible" "200" "$PAGE"

# 结果汇总
echo ""
echo "═══════════════════════"
green "通过: $PASS"
if [ $FAIL -gt 0 ]; then
  red "失败: $FAIL"
else
  green "失败: $FAIL"
fi
echo "═══════════════════════"

rm -f "$COOKIE"
exit $FAIL
```
