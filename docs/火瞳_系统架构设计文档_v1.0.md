## 1. 文档概述

### 1.1 目的

本文档定义火瞳系统的完整技术架构，涵盖视觉AI引擎与数据引擎的集成方案、数据模型、API规约、部署架构、安全体系和运维体系。为研发团队提供可执行的技术蓝图。

### 1.2 与现有文档的关系

| 文档              | 定位                | 本文引用关系                  |
| --------------- | ----------------- | ----------------------- |
| 融合PRD v5.1      | 产品需求（What & Why）  | 功能编号N01-N18对应本文架构组件     |
| 数据引擎技术设计文档 v1.0 | 数据引擎模块设计（How-模块级） | 本文升级为系统级架构，含集成/部署/安全/运维 |
| 仓库现有代码          | 已落地实现（98文件/176测试） | 本文标注"已有"的组件均指仓库现有实现     |

### 1.3 设计原则

| 原则        | 含义                                 | 体现                              |
| --------- | ---------------------------------- | ------------------------------- |
| **最小侵入**  | 不修改已有核心模块，新增独立目录                   | `data_engine/` 独立于 `event_hub/` |
| **复用模式**  | 新代码遵循已有架构模式                        | 路由自动发现、EventStore扩展、RBAC复用      |
| **渐进降级**  | 每层可独立降级，不阻塞上层                      | 四级预测降级链 L1→L2→L3→L4             |
| **事件驱动**  | 引擎间通过事件解耦                          | 视觉→库存通过EventStore订阅             |
| **双后端兼容** | SQLite(dev) + PostgreSQL(prod) 同接口 | 新表同时提供两套schema                  |

## 3. 视觉引擎与数据引擎集成接口规约

### 3.1 事件协议定义

视觉引擎与数据引擎通过 **EventStore 事件订阅机制** 解耦。视觉引擎产出事件 → EventStore分发 → 数据引擎消费 → 触发库存/损耗/订货联动。

#### 3.1.1 事件总线扩展

现有 `EventStore` 基于 `deque(maxlen=500)` 的内存事件队列，通过 `_on_persist` 回调持久化。新增 **订阅者注册机制**：

```python
# 在 hub_core.py 的 EventStore 类中新增（不修改已有方法）

class EventSubscriber:
    """事件订阅者接口。数据引擎实现此接口消费视觉事件。"""
    def on_event(self, store_id: str, event: dict) -> None:
        ...

# EventStore 新增方法
class EventStore:
    def __init__(self, ...):
        ...
        self._subscribers: list[EventSubscriber] = []  # 新增

    def subscribe(self, subscriber: EventSubscriber) -> None:
        """注册事件订阅者。不修改已有 add_event 逻辑。"""
        self._subscribers.append(subscriber)

    def add_event(self, event: dict) -> dict:
        """已有方法不变，末尾追加通知。"""
        result = self._existing_add_event(event)  # 原逻辑
        for sub in self._subscribers:
            try:
                sub.on_event(self.store_id, result)
            except Exception as exc:
                print(f"[EventStore] subscriber error: {exc}")
        return result
```

#### 关键调用链：视觉检测 → 订货建议（完整闭环）

```
1. 边缘YOLO检测到3盘毛肚废弃
   → event: vlm_waste_estimate {sku:毛肚, count:3}

2. EventStore.add_event() 存储事件
   → 通知 InventorySubscriber.on_event()

3. InventorySubscriber:
   3a. N03库存台账扣减 → inventory_ledger INSERT (change:-3, type:waste)
   3b. N04损耗分析 → loss_analysis INSERT (sku:毛肚, loss_count:3, root_cause:待分析)

4. N04损耗分析异步触发根因分析:
   → 对比预测值 vs 实际 → 偏差 > 阈值 → root_cause:采购过量

5. N01销量预测引擎触发重算:
   → 读取 sales_daily 最近90天 → L1/L2/L3预测 → 更新明日预测

6. N02订货顾问:
   → 预测需求 - 当前库存 - 安全库存 = 补货量
   → 生成 procurement_order (status:suggested)
   → N05供应商评分加权排序 → suggested_supplier

7. AlertGateway推送:
   → 损耗率 > 基线1.5倍 → 微信告警推送

8. (次日) N17预测回灌:
   → 实际消耗 vs 预测偏差 → 回灌训练数据 → 模型自校准
```

```sql
-- ═══════════════════════════════════════════════════════
-- N01/N03/N04 共享：商品目录
-- ═══════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS product_catalog (
    sku_id          TEXT PRIMARY KEY,
    sku_name        TEXT NOT NULL,
    category        TEXT NOT NULL,        -- 鲜肉/蔬菜/锅底/酒水/凉菜/主食
    sub_category    TEXT,                 -- 牛肉/羊肉/叶菜/根茎...
    unit            TEXT NOT NULL,        -- 盘/份/瓶/斤
    shelf_life_days INTEGER,              -- 保质期(天)
    cost_price      REAL NOT NULL,        -- 成本价(元)
    supplier_id     TEXT,                 -- 主供应商
    min_order_qty   REAL DEFAULT 1,       -- 最小起订量
    is_active       INTEGER DEFAULT 1,
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL,
    FOREIGN KEY (supplier_id) REFERENCES supplier(supplier_id)
);
CREATE INDEX IF NOT EXISTS idx_pc_category ON product_catalog(category);
CREATE INDEX IF NOT EXISTS idx_pc_supplier ON product_catalog(supplier_id);

-- ═══════════════════════════════════════════════════════
-- N01：日销量时序
-- ═══════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS sales_daily (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    store_id        TEXT NOT NULL,
    sku_id          TEXT NOT NULL,
    date            TEXT NOT NULL,        -- YYYY-MM-DD
    quantity        REAL NOT NULL DEFAULT 0,
    revenue         REAL DEFAULT 0,
    hour_dist       TEXT DEFAULT '{}',    -- JSON: {"11":5,"12":12,"18":8,"19":15}
    time_period     TEXT,                 -- lunch/dinner/latenight (评审建议新增)
    source          TEXT DEFAULT 'pos',   -- pos/erp/manual/estimated
    created_at      TEXT NOT NULL,
    UNIQUE(store_id, sku_id, date),
    FOREIGN KEY (sku_id) REFERENCES product_catalog(sku_id)
);
CREATE INDEX IF NOT EXISTS idx_sd_store_sku_date ON sales_daily(store_id, sku_id, date DESC);
CREATE INDEX IF NOT EXISTS idx_sd_store_date ON sales_daily(store_id, date DESC);
CREATE INDEX IF NOT EXISTS idx_sd_time_period ON sales_daily(time_period);

-- ═══════════════════════════════════════════════════════
-- N03：库存台账
-- ═══════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS inventory_ledger (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    store_id        TEXT NOT NULL,
    sku_id          TEXT NOT NULL,
    date            TEXT NOT NULL,
    change_qty      REAL NOT NULL,        -- 正=入库, 负=出库/损耗
    change_type     TEXT NOT NULL,        -- receiving/waste/sale/adjust/return
    balance_after   REAL NOT NULL,        -- 变更后余额
    ref_event_id    TEXT,                 -- 关联events.event_id
    ref_order_id    TEXT,                 -- 关联procurement_order
    operator        TEXT,                 -- 操作人
    note            TEXT,
    created_at      TEXT NOT NULL,
    FOREIGN KEY (sku_id) REFERENCES product_catalog(sku_id)
);
CREATE INDEX IF NOT EXISTS idx_il_store_sku_date ON inventory_ledger(store_id, sku_id, date DESC);
CREATE INDEX IF NOT EXISTS idx_il_store_date ON inventory_ledger(store_id, date DESC);
CREATE INDEX IF NOT EXISTS idx_il_change_type ON inventory_ledger(change_type);

-- ═══════════════════════════════════════════════════════
-- N02：采购订货单
-- ═══════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS procurement_order (
    order_id        TEXT PRIMARY KEY,
    store_id        TEXT NOT NULL,
    sku_id          TEXT NOT NULL,
    suggested_qty   REAL NOT NULL,
    suggested_supplier TEXT,              -- 供应商ID
    status          TEXT DEFAULT 'suggested', -- suggested/approved/ordered/received/cancelled
    priority        TEXT DEFAULT 'normal',    -- urgent/high/normal/low
    predicted_demand REAL,                -- N01预测的需求量
    current_stock   REAL,                 -- 当前库存
    safety_stock    REAL,                 -- 安全库存
    unit_cost       REAL,                 -- 单价(快照)
    total_cost      REAL,                 -- 总成本(快照)
    created_at      TEXT NOT NULL,
    approved_by     TEXT,
    approved_at     TEXT,
    executed_qty    REAL,                 -- 实际执行量(N17回灌用)
    executed_at     TEXT,
    prediction_error REAL,                -- 预测偏差(N17回灌用)
    FOREIGN KEY (sku_id) REFERENCES product_catalog(sku_id),
    FOREIGN KEY (suggested_supplier) REFERENCES supplier(supplier_id)
);
CREATE INDEX IF NOT EXISTS idx_po_store_status ON procurement_order(store_id, status);
CREATE INDEX IF NOT EXISTS idx_po_store_date ON procurement_order(store_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_po_priority ON procurement_order(priority);

-- ═══════════════════════════════════════════════════════
-- N05：供应商
-- ═══════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS supplier (
    supplier_id     TEXT PRIMARY KEY,
    name            TEXT NOT NULL,
    contact         TEXT,
    phone           TEXT,
    rating          TEXT DEFAULT 'B',     -- A/B/C/D
    on_time_rate    REAL DEFAULT 0.0,     -- 准时交货率
    quality_rate    REAL DEFAULT 0.0,     -- 质量合格率
    price_index     REAL DEFAULT 1.0,     -- 价格指数(1.0=市场均价)
    total_orders    INTEGER DEFAULT 0,
    is_active       INTEGER DEFAULT 1,
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_supplier_rating ON supplier(rating);

-- ═══════════════════════════════════════════════════════
-- N04：损耗分析
-- ═══════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS loss_analysis (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    store_id        TEXT NOT NULL,
    sku_id          TEXT NOT NULL,
    date            TEXT NOT NULL,
    loss_qty        REAL NOT NULL DEFAULT 0,
    loss_value      REAL NOT NULL DEFAULT 0,
    loss_type       TEXT,                 -- 备餐废弃/过期/品质问题/运输损耗
    root_cause      TEXT,                 -- 采购过量/预测偏差/存储不当/突发客流
    trend           TEXT,                 -- rising/stable/falling
    compared_avg    REAL,                 -- 对比7日均值
    compared_ratio  REAL,                 -- 比率(1.5=超基线50%)
    suggestion      TEXT,                 -- AI建议
    created_at      TEXT NOT NULL,
    FOREIGN KEY (sku_id) REFERENCES product_catalog(sku_id)
);
CREATE INDEX IF NOT EXISTS idx_la_store_sku_date ON loss_analysis(store_id, sku_id, date DESC);
CREATE INDEX IF NOT EXISTS idx_la_store_date ON loss_analysis(store_id, date DESC);
CREATE INDEX IF NOT EXISTS idx_la_root_cause ON loss_analysis(root_cause);
```

### 7.2 多租户隔离

现有机制：`store_id` 作为租户标识，贯穿所有数据操作。

- 所有6张新表均含 `store_id` 字段（`supplier` 和 `product_catalog` 例外，为品牌级共享表）

    items = inventory_book.get_current(store_id)  # ← 不可能跨租户

### 9.2 各Sprint 0结论下的架构调整

#### V1(POS数据)通过 → 架构不变

```
pos_bridge.fetch_daily_sales() → REST API → sales_daily INSERT
预测引擎正常：L1→L2→L3→L4
```

#### V1(POS数据)不通过 → 数据采集层降级

```
# 降级路径1：Excel导入
pos_bridge.fetch_daily_sales() → 读取POS导出的Excel → 解析 → sales_daily INSERT
# 降级路径2：ERP出库反推
pos_bridge.fetch_daily_sales() → erp_bridge.get_outbound() → 反推销量
# 降级路径3：手动录入
前端提供手动录入界面 → POST /api/v1/inventory/sales/sync
```

影响：预测只能跑L1(移动平均)，L2/L3因数据延迟和颗粒度不足暂不可用。架构不变，只是数据源切换。

#### V2(回测)通过 → 算法架构不变

四级预测降级链按设计运行。

#### V2(回测)不通过 → 新增火锅周期因子引擎

在 `data_engine/hotpot_factors.py` 中实现规则补丁：

```python
HOTPOT_PERIOD_FACTORS = {
    "weekday": {
        0: 0.85,  # 周一
        1: 0.85,  # 周二
        2: 0.90,  # 周三
        3: 0.95,  # 周四
        4: 1.10,  # 周五
        5: 1.50,  # 周六
        6: 1.35,  # 周日
    },
    "holiday": 2.0,       # 法定节假日
    "weather": {
        "rain": 0.70,     # 雨天
        "hot": 0.85,      # 高温>35°C
        "cold": 1.15,     # 寒潮<5°C
    },
    "season": {
        "summer": 0.90,   # 夏季(火锅淡季)
        "winter": 1.25,   # 冬季(火锅旺季)
    },
}

# 在L1移动平均基础上叠加因子
def apply_factors(base_forecast, date, weather="normal"):
    weekday_factor = HOTPOT_PERIOD_FACTORS["weekday"][date.weekday()]
    season_factor = HOTPOT_PERIOD_FACTORS["season"].get(get_season(date), 1.0)
    weather_factor = HOTPOT_PERIOD_FACTORS["weather"].get(weather, 1.0)
    holiday_factor = 2.0 if is_holiday(date) else 1.0
    return base_forecast * weekday_factor * season_factor * weather_factor * holiday_factor
```

影响：预测引擎增加一层因子修正，架构不变，只是L1层输出经过 `apply_factors()` 后处理。

#### V3(预访谈)通过 → P0不变

N01-N06维持P0，按10周计划开发。

#### V3(预访谈)不通过 → 功能优先级调整

N01-N06降为P1，P0改为N03(库存台账)+N04(损耗分析)——这两个不依赖POS数据，直接消费视觉事件。

影响：Sprint计划重排，但架构设计不变。

### 9.3 架构设计稳定性结论

> **本架构设计在所有Sprint 0结论下均不需要结构性调整。**
>
> V1不通过 → 数据采集层切换（架构不变）  
> V2不通过 → 新增因子修正层（架构不变）  
> V3不通过 → 功能优先级调整（架构不变）
>
> 唯一的变量是开发顺序和算法层级，不是架构本身。
