## 1. 功能统计准确性

### 1.1 🔴 P0：PRD 内部功能总数三处矛盾

**证据**：

| PRD 出现位置 | 声称功能数 | 行号 |
|-------------|:--------:|:----:|
| §1.5 产品底层设计哲学 | **71 项** | L86 |
| §3A 经营闭环哲学 | **114 项** | L698 |
| §3.5 功能统计表 (合计行) | **129 项** | L686 |

**根本原因**：PRD 经过 v5.3a→v5.3e→v5.3g→v5.3i 多版迭代，§1.5 残留 v5.3e 的数字 (71)，§3A 残留中间版本数字 (114)，仅 §3.5 统计表更新到了最新 129。但 §1.5 和 §3A 的章节标题未标注"v5.3e 基线"或"v5.3g 基线"，读者会误认为全文统一。

**严重程度**：🔴 高 — 功能总数是产品规模的核心指标，三处矛盾导致读者无法判断产品实际规模。

**修正建议**：
1. §1.5 标题改为 "1.5 产品底层设计哲学（三大支柱）— v5.3e 基线说明"
2. §3A 标题加入 "（截至 v5.3g 版本，114 项功能完整覆盖）"
3. 或：统一更新 §1.5/§3A 为 129 项

## 2. 代码量参数一致性

### 2.1 🔴 P0：总代码行数不准 — 38,179 行 vs 实际 43,569 行

**系统架构总体设计 v2.0 L6 声称**：
> "代码基线：38,179行 / 189个py文件(边缘94+平台95) / 45个测试 / 覆盖率85%"

**实际测量** (`wc -l *.py`)：
| 指标 | 声称为 | 实测为 | 偏差 |
|------|:-----:|:-----:|:----:|
| 总 .py 行数 | 38,179 | **43,569** | +5,390行 (+14.1%) |
| 边缘 .py 文件 | 94 | 94 | ✓ |
| 平台 .py 文件 | 95 | 95 | ✓ |
| 总 .py 文件 | 189(仅边缘+平台) | **262** (全量) | 缺73个 |
| 测试文件 | 45 | 45 | ✓ |

**根本原因**：189 = 边缘94 + 平台95，但缺少 `deploy/`、`tests/`、根目录等 73 个 .py 文件。而且 `38,179` 是过时的统计（可能来自更早的代码快照）。

**严重程度**：🔴 高 — 代码规模是架构文档核心参数，14% 偏差 + 漏计 73 个文件误导读者对项目规模的判断。

**修正建议**：
- 总行数：`43,569`
- 总文件数：`262` 或明确标注 "189（边缘+平台核心），262（含测试/部署全量）"

```
保守(展会): 单店年省≥¥15万 / 回本8周 / ROI 6x
内部(测算): 单店年省≥¥28万 / 回本5周 / ROI 11x
```
