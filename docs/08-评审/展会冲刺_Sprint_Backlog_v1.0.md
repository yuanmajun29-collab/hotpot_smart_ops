## 3. DoR / DoD 定义

### 3.1 Definition of Ready (DoR) — 任务准入标准

一个 Task 可以进入 Sprint 开发，当且仅当满足以下 **全部** 条件：

| # | 检查项 | 说明 | 验证方式 |
|---|--------|------|----------|
| **DR-1** | ✅ 有对应的设计文档 | 代码必须基于设计开发（Design-First原则） | 文档存在于 `docs/04-技术设计/` 或 PRD 中有明确需求描述 |
| **DR-2** | ✅ 需求来源可追溯 | 任务必须关联到 PRD 功能点或用户故事 | Task 描述中包含 "对应PRD: Lxxx" 或 "Epic: xxx" |
| **DR-3** | ✅ 估算合理且有边界 | 任务粒度适中（≤1天工作量），验收标准明确 | 包含预估工时和 DoD 检查清单 |
| **DR-4** | ✅ 技术方案可行 | 无技术阻塞，依赖项已识别并列出 | 前置依赖列表完整，或标注"无阻塞" |
| **DR-5** | ✅ 代码规范明确 | 遵循项目编码规范（Python 3.8兼容、类型注解等） | 参考 `docs/04-开发基线/PROJECT_BASELINE_V5_2.md` |

### 3.2 Definition of Done (DoD) — 任务完成标准

一个 Task 标记为 Done，当且仅当满足以下 **全部** 条件：

| # | 检查项 | 说明 | 验证方式 |
|---|--------|------|----------|
| **DD-1** | ✅ 代码已完成并提交 | 代码已 commit 到 feature 分支 | Git log 可查 |
| **DD-2** | ✅ 测试通过 | 核心功能有对应测试用例且通过 | pytest 或手动测试记录 |
| **DD-3** | ✅ 无已知阻塞性Bug | P0/P1 Bug 为 0 | Issue tracker 或 Known Issues 列表 |
| **DD-4** | ✅ 文档同步更新 | 如有设计变更，文档已同步 | 文档最后修改时间 ≥ 代码提交时间 |
| **DD-5** | ✅ Code Review 通过 | 代码符合项目规范（可选：同行评审） | 自查清单或 Review 记录 |
