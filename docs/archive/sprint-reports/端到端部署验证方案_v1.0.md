## 🚨 6. 风险缓解措施

### 6.1 技术风险

| 风险 | 缓解措施 | 应急方案 |
|------|----------|----------|
| psycopg2安装失败 | 使用asyncpg备选 | 回退到SQLite模式（降级运行） |
| Docker PG端口冲突 | 自动检测可用端口 | 使用5433/5434等备用端口 |
| SQL语法兼容性问题 | 先在psql命令行手动测试 | 修复SQL后重试 |
| 权限不足（CREATE TABLE） | 使用超级用户账号 | 提前创建数据库和用户权限 |

### 6.2 流程风险

| 风险 | 缓解措施 | 应急方案 |
|------|----------|----------|
| 腾讯云无法直接SSH | 通过Web控制台/宝塔面板操作 | 提前准备SQL脚本手动执行 |
| PG服务未安装 | 在deploy脚本中自动安装 | 使用Docker PG替代 |
| 防火墙阻止5432 | 仅本地验证，云端通过Unix Socket | 调整为localhost连接 |

### B. 故障排查指南

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| `psycopg2.OperationalError: could not connect` | PG未启动或端口错误 | `docker ps` 检查容器状态 |
| `permission denied for schema public` | 用户权限不足 | 使用超级用户或GRANT权限 |
| `relation "audit_events" does not exist` | Schema未初始化 | 先执行 `db_init audit` |
| `duplicate key value violates unique constraint` | 重复插入 | UPSERT语句已处理，检查数据源 |
| `Gateway返回500` | PG连接池耗尽 | 检查连接字符串和池配置 |
