## 一、功能统计表（§3.5）逻辑错误

### 🔴 P0：功能数量不一致（严重）

**问题**：§3.5 表格声称 P0 行「仓库已有=12」，但实际 P0 的 K 系列功能共 13 项拥有代码基础：

| ID | 模块 |
|----|------|
| K01 | 废料实时检测 |
| K02 | 废料自动计数 |
| K03 | 每日浪费报告 |
| K31 | 出品质检 ← **被遗漏** |
| K04 | 桌态实时检测 |
| K05 | 空桌提醒 |
| K19 | 冷柜温度监控 |
| K20 | 后厨温湿度 |
| K21 | 保质期预警 |
| K22 | IoT Dashboard |
| K06 | 单店 Dashboard |
| K07 | 日报自动推送 |
| K08 | 设备管理 |

**证据**：CLAUDE.md 及 `PRD_V5_2_CODE_ALIGNMENT.md` 均将 K31 列为「代码基础」。

**建议修正**：P0 行应改为「仓库已有=13，合计=25」

---

### 🔴 P1：N20 重复计数 + A04 归属错误（严重）

**问题**：§3.5 P1 行 N/S/A 列公式为：
```
3+3(N19-N21)+1(N20)+2(K33-K34)+2(K35-K36)+1(A04)+1(N18)+1(N22)+1(A05)
```

存在两个错误：

1. **N20 重复计数**：`3(N19-N21)` 已包含 N20，再加 `+1(N20)` 重复。
2. **A04 归属错误**：A04「供应商协同端」在 PRD §3.3 P2 功能区，不应出现在 P1 统计中。

**建议修正**：
- 移除 `+1(N20)` 和 `+1(A04)`
- P1 N/S/A 新功能 = 3(N07-N09) + 3(N19-N21) + 2(K33-K34) + 2(K35-K36) + 1(N18) + 1(N22) + 1(A05) = **13**
- P1 合计 = 13（仓库已有）+ 13（新）= **26**（表格写 27）

---

### 🟡 P2：A04 遗漏（中等）

**问题**：§3.5 P2 行 N/S/A 列为 `4(+N17)+1(S04)`，漏计了 A04「供应商协同端」。

**证据**：PRD §3.3 P2 功能表包含 A04（状态：待开发）。

**建议修正**：P2 N/S/A 应改为 `4(+N17)+1(S04)+1(A04)` = 6，合计 = 3 + 6 = **9**（表格写 8）

---

### 🟡 合计行连锁影响

若以上修正全部执行：

### 🟡 损耗率阈值：概念混淆风险（需标注）

| 位置 | 数值 | 含义 |
|------|------|------|
| PRD §5.1 业务指标 | 试点期≤8%→验证期≤5%→成熟期≤3% | **整体经营目标**（分阶段） |
| `loss_analyzer.py:L38-45` | 肉类 5%, 蔬菜 8%, 冻品 3%, 底料 2%, 蘸料 2% | **per-SKU 类别告警阈值**（单日） |

这两个不是同一概念：PRD 说的是「全店综合损耗率」的阶段性目标，代码中是「单 SKU 单日」的告警触发阈值。PRD 未区分说明，易被误读为代码中的阈值。

**建议**：在 PRD §5.1 中加注「综合目标」，或在 §4（N04 损耗成本闭环说明）中区分 per-SKU 告警阈值 vs 综合经营目标。

---

### 🟡 MAPE 门槛：代码中未硬编码

PRD §6.2 规定：
> L1 MAPE ≤45% 才可进入"可用"评估；45%-55% 只能带校准试运行；>55% 不进入订货建议阶段。

**证据**：`sales_predictor.py` 的 `evaluate()` 方法只输出 MAPE 值，不做阈值判断；`order_advisor.py` 也没有 MAPE 门槛检查。

**建议**：明确此门槛是「业务流程规则」而非代码硬限制，避免开发人员以为代码已内置此逻辑。

### 🟡 N05 命名与代码不一致

| 位置 | 命名 | 
|------|------|
| PRD §3.1 N05 | **订货偏差分析** |
| 源代码 `supplier_scorer.py` | **供应商评分引擎 (Supplier Scorer)** |

PRD 中 N05 被描述为「订货偏差分析」（对比预估 vs 实际消耗），但实际代码 `supplier_scorer.py` 实现的是「供应商评分」。PRD 的 N02 提到「供应商分配按 N05 评分卡加权」，说明 N05 被视作评分卡，但 N05 的功能描述却是偏差分析。

**证据**：
- PRD N05 EARS：「对比采购预估量与实际消耗量，生成偏差率和趋势。偏差数据自动回灌预测模型训练集」
- 代码文件注释：「火瞳 · 数据引擎 — N05 供应商评分引擎」

**建议**：明确 N05 是纯供应商评分（与代码对齐），偏差分析功能归属 N17「预测自动回灌训练」。
