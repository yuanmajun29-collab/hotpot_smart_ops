# 火瞳项目基线 v5.2

## 产品定位

火瞳是冯校长火锅浙江总代的连锁 AI 运营中台。当前先服务椒江店与玉环店，验证后再形成浙江区域新店标准，最后才考虑向体系内或外部输出。

## 当前阶段

当前阶段为两店真实运营验证，而不是外部 SaaS 获客或全面产品化。

视觉引擎负责采集后厨、前厅和食安事件；数据引擎负责 POS、库存、损耗、预测和订货建议。任何正式库存或采购动作都必须由门店角色确认，系统只提供证据和建议。

## 验证结论的分级

所有项目结论必须标注为以下四类之一：

1. 设计：PRD、架构或方案中的目标。
2. 代码验证：单元测试、语法编译或本地功能测试。
3. 模拟验证：由样例、生成脚本或模拟事件得出的结果。
4. 真实门店验证：可追溯到原始 POS 导出、现场事件、门店负责人确认和时间范围的结果。

没有原始来源与负责人复核的指标，不得作为真实 ROI、正式门店标准或对外销售案例。

## 分支整合原则

- `origin/main` 是当前代码整合起点。
- `feature/fusion-phase0-2` 的数据引擎与主分支实现存在重叠；不得整支直接合并，需逐模块择一。
- `feat/iot-stream-context-engine` 只能提取实际 IoT 代码，不能带入协调器状态或其他内部文件。
- 任何合并前必须通过语法编译、自动化测试和两店 UAT 验收。
