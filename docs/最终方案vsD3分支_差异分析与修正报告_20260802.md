## 一、最终方案核心原则回顾

### 1.1 产品定位（第二章）

| 维度 | 定义 |
|------|------|
| **是什么** | 面向连锁餐饮的 **AI智能体运营系统** |
| **不是什么** | ❌ 传统ERP替代品 |
| **核心价值** | 把门店现场事实转成 → 可处理的事件、可解释的建议、可追踪的任务、**可验证的经营改善** |

### 1.2 三条优先业务闭环（第六章）

#### 闭环1️⃣ 后厨损耗闭环 ✅ **基本符合**
```
视觉/VLM发现废料 → Edge上报结构化事件 → Hub计算损耗趋势 
→ 后厨Agent推送确认原因 → 超阈值升级店长 → 任务复核 → 结果回流
```

**当前实现**: S1场景已验证通过（废料检测+损耗估算+SOP合规）

#### 闭环2️⃣ 预测—库存—采购闭环 ⚠️ **存在P0违规**
```
POS/库存/天气/节假日/供应商履约等数据 → 预测和订货建议 
→ 采购Agent解释风险与建议 → 人工调整和审批 
→ 推送ERP待办或人工下单 → 到货/销售/偏差回流
```

**⚠️ 方案明确要求**: **"AI 不自动创建正式采购订单"**

#### 闭环3️⃣ 冻品收货与供应商闭环 🟡 **部分实现**
```
货品标准与采购订单 → 温度/重量/图片/VLM辅助质检 
→ 收货/质检人员确认 → 入库/部分通过/退换货 → 供应商评分
```

**当前状态**: VLM仍为Mock（表格21指出）

### 1.3 岗位Agent行动边界（第七章 表格35）

| Agent | 第一阶段职责 | **行动边界（红线）** |
|-------|------------|-------------------|
| **店长Agent** | 今日异常、经营复盘、任务优先级、跨岗位协调 | 可创建/跟进任务；**关键经营动作需授权确认** |
| **后厨Agent** | 备货、SOP、损耗、温控、出品风险指导 | 可提示与生成整改任务；**不直接扣减库存** |
| **采购Agent** | 预测、库存风险、比价、订货建议、到货跟踪 | 可生成建议和待办；**正式下单必须审批** ✅ |
| **收货/质检Agent** | 来货核验、VLM辅助质检、异常与复核 | 可建议通过/驳回；**最终签字由授权人员完成** ✅ |

## 二、差异详细分析

### 🔴 P0-1: IP-5逻辑严重违规 — 自动创建PO

#### 方案要求

**第六章 闭环2️⃣** (段落31):
> "AI 不自动创建正式采购订单"

**第七章 表格35** (采购Agent):
> "可生成建议和待办；**正式下单必须审批**"

#### 当前实现（❌ 违规）

**文件**: `hotpot_platform/cloud/integration/integration_engine.py:441-479`

```python
def handle_suggestion_accepted(event: Event):
    """AI采购建议被采纳后自动创建采购订单"""  # ← 注释就说明问题了！

    # ... 获取建议详情 ...

    # 🔴 问题代码：直接调用PO创建，无人工审批环节
    po = self._manager.create_po_from_suggestion(
        suggestion_id=suggestion_id,
        sku=sku,
        qty=qty,
        supplier_id=supplier_id,
    )
    
    if po:
        logger.info(f"[IP-5] ✅ 成功创建PO: {po.order_no}")
        # 还会触发IP-3联动...
        self.on_po_created(po_id=po.po_id, ...)
```

**调用链路**:
```
用户点击"采纳建议" 
  → PUT /api/v1/assistant/suggestions/{id}/accept
    → manager.accept_suggestion(id)
      → engine.on_suggestion_accepted(id)  // 发布事件
        → handle_suggestion_accepted()     // IP-5处理器
          → create_po_from_suggestion()    // 🔴 直接创建正式PO！
```

#### 影响评估

| 维度 | 影响 |
|------|------|
| **合规性** | ❌ 违反方案核心原则 |
| **安全性** | ⚠️ AI可绕过审批自动下单（资金风险） |
| **可控性** | ❌ 无法追溯谁批准了这笔采购 |
| **展会演示** | ⚠️ 可能被质疑"AI是否越权" |

#### 修正方案

**新流程**（符合方案要求）:
```
用户采纳建议 
  → 标记建议为"已采纳" 
  → 创建"待审批采购任务"（Task, status=pending_approval）
  → 推送给采购负责人（通知）
  → [人工在UI上审批] 
  → 审批通过后才调用 create_po_from_suggestion()
```

**代码修改点**:

1. **`integration_engine.py` IP-5处理器**
   ```python
   def handle_suggestion_accepted(event: Event):
       """AI采购建议被采纳后生成待办任务（需人工审批）"""
       # 不再直接创建PO！
       # 改为创建待审批任务
       task = self._manager.create_purchase_approval_task(
           suggestion_id=suggestion_id,
           sku=sku,
           qty=qty,
           supplier_id=supplier_id,
           target_role="purchaser",  # 推送给采购负责人
           priority="high",
       )
       
       if task:
           logger.info(f"[IP-5] ✅ 已生成采购审批任务: {task['id']}")
   ```

2. **新增方法 `create_purchase_approval_task()`**
   ```python
   @classmethod
   def create_purchase_approval_task(cls, suggestion_id, sku, qty, supplier_id, target_role, priority):
       """从AI建议创建待审批采购任务"""
       task = {
           "id": f"TASK-PO-{uuid4().hex[:8].upper()}",
           "type": "purchase_approval",
           "suggestion_id": suggestion_id,
           "title": f"审批采购: {sku} x{qty}",
           "status": "pending_approval",  # 待审批状态
           "target_role": target_role,
           "priority": priority,
           "created_at": datetime.now().isoformat(),
           "action_params": {
               "sku": sku,
               "qty": qty,
               "supplier_id": supplier_id,
           },
           "approval_workflow": {  # 审批流程元数据
               "created_by": "ai_agent",  # 由AI生成
               "approved_by": None,      # 等待人工审批
               "approved_at": None,
               "po_created": False,      # PO尚未创建
           }
       }
       cls._task_cache[task["id"]] = task
       return task
   ```

3. **新增API端点 `POST /api/v1/tasks/{task_id}/approve`**
   ```python
   @router.post("/tasks/{task_id}/approve")
   async def approve_purchase_task(task_id: str, session: dict = Depends(get_current_session)):
       """人工审批采购任务 → 创建正式PO"""
       task = SupplyChainManager.get_task(task_id)
       if not task or task.get("type") != "purchase_approval":
           raise HTTPException(404, "任务不存在或类型错误")
       
       if task.get("status") != "pending_approval":
           raise HTTPException(400, "任务状态不允许审批")
       
       # 调用原有的PO创建逻辑
       po = SupplyChainManager.create_po_from_suggestion(
           suggestion_id=task["suggestion_id"],
           **task["action_params"]
       )
       
       if po:
           # 更新任务状态
           task["status"] = "approved"
           task["approval_workflow"]["approved_by"] = session["user"]["role"]
           task["approval_workflow"]["approved_at"] = datetime.now().isoformat()
           task["approval_workflow"]["po_created"] = True
           task["approval_workflow"]["po_number"] = po.order_no
           
           return {"code": 0, "data": {"task": task, "po": po.order_no}}
       
       raise HTTPException(500, "PO创建失败")
   ```

### 🔴 P0-2: Agent Gateway缺失 — 无统一管控入口

#### 方案要求

**第八章 表格39 (P0修正项)**:
> "**Agent Gateway**: 自然语言查询、工具白名单、角色权限、审批、幂等、审计和回滚统一从网关进入"

#### 当前实现

**现状**: ❌ 无Agent Gateway
- 各API端点直接暴露，无统一入口
- 无工具白名单机制
- 无操作审计日志
- 无权限细粒度控制

#### 修正方案（简化版，展会前可实现）

创建轻量级Agent Gateway中间件:

```python
# edge/edge-ui/middleware/agent_gateway.py

class AgentGatewayMiddleware:
    """岗位Agent统一网关（轻量版）"""
    
    # 工具白名单：各Agent允许的操作
    TOOL_WHITELIST = {
        "store_manager": ["view_dashboard", "create_task", "approve_task", "view_reports"],
        "kitchen_chef": ["view_prep_list", "create_sop_task", "view_waste_alert"],
        "purchaser": ["view_suggestions", "accept_suggestion", "approve_purchase"],  # 注意：无create_po
        "receiver": ["view_receiving", "submit_qc_result", "request_rerun"],
    }
    
    # 需要审批的操作列表
    ACTIONS_REQUIRE_APPROVAL = [
        "create_po",          # 创建PO（已移除，改为approve_purchase_task）
        "approve_receiving_d", # D级品项通过
        "adjust_inventory",    # 库存调整
    ]
    
    async def __call__(self, request: Request, call_next):
        path = request.url.path
        
        # 只拦截Agent相关API
        if not path.startswith("/api/v1/assistant/") and not path.startswith("/api/v1/tasks/"):
            return await call_next(request)
        
        # 1. 角色权限检查
        user_role = request.state.user.get("role", "guest") if hasattr(request.state, 'user') else "guest"
        action = self._extract_action(path, request.method)
        
        if action and not self._is_allowed(user_role, action):
            return JSONResponse(
                status_code=403,
                content={"code": 403, "msg": f"角色{user_role}无权执行{action}"}
            )
        
        # 2. 审计日志
        start_time = time.time()
        response = await call_next(request)
        process_time = time.time() - start_time
        
        # 记录审计日志
        self._log_audit(user_role, action, request, response.status_code, process_time)
        
        return response
```

### 🟡 P1-3: 架构层次映射偏差

#### 方案要求（第三章 表格17 - 7层架构）

| 层级 | 目标职责 | 当前分支状态 | 差距 |
|------|---------|------------|-----|
| L1 感知与连接 | 摄像头/IoT/POS/ERP等输入 | 已有模块骨架 | 多厂商连接未验证 |
| L2 边缘计算 | 视频分析/设备管理/离线缓存 | Edge Agent已有 | ✅ 基本符合 |
| L3 数据治理 | 主数据/事件/质量/权限/审计 | Hub+RBAC基础 | ⚠️ 缺完整治理 |
| L4 业务平台 | 预测/损耗/收货/采购/供应商 | 主Hub较完整 | D1-D3属原型 |
| L5 AI大脑与Agent | 知识/规则/模型/工具/上下文 | 待办/建议/检索框架存在 | ❌ 自然语言Agent未产品化 |
| L6 岗位Agent | 五角色协同（店长/后厨/采购/收货/区域） | 四角色面板已有 | ⚠️ 行动边界不清 |
| L7 人工确认与执行 | 人确认关键动作，结果回流学习 | 有确认按钮 | ⚠️ 缺学习回流 |

#### 关键差距: L5-L7 未形成闭环

**方案强调**（第十一章）:
> "现场自动感知，数据统一治理，平台形成判断，**Agent找对人并指导执行**，**人确认关键动作**，结果持续回流学习"

**当前问题**:
- Agent推送建议后，缺乏"人确认→执行→结果反馈→学习"的完整闭环
- 特别是IP-5：人"采纳建议"后，系统直接执行（创建PO），跳过了"人确认执行"这一步

## 五、结论与建议

### 核心结论

1. **当前D3集成实现了技术可行性验证**（EventBus、IntegrationEngine、5个IP处理器），但在**业务逻辑层面偏离了最终方案的核心原则**。
