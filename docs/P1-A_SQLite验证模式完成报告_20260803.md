## 🔧 核心技术实现

### 1. PG→SQLite SQL转换引擎 (`_convert_pg_to_sqlite()`)

解决的核心问题：**PostgreSQL和SQLite语法差异巨大**

```python
# 输入 (PG语法):
CREATE TABLE audit_events (
    id BIGSERIAL PRIMARY KEY,
    audit_id UUID NOT NULL DEFAULT uuid_generate_v4(),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    request_params JSONB DEFAULT '{}',
    is_frozen BOOLEAN DEFAULT FALSE
);

# 输出 (SQLite兼容):
CREATE TABLE IF NOT EXISTS audit_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    audit_id VARCHAR(36) NOT NULL DEFAULT '',
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    request_params TEXT DEFAULT '{}',
    is_frozen INTEGER DEFAULT 0
);
```

**10种转换规则覆盖**:
- 类型替换: BIGSERIAL, SERIAL, TIMESTAMPTZ, UUID, JSONB, INET, BOOLEAN, TEXT[]
- 函数替换: NOW(), datetime('now'), uuid_generate_v4(), TRUE/FALSE
- 语句删除: CREATE EXTENSION, COMMENT ON, CREATE FUNCTION/TRIGGER/VIEW, #注释
- 约束处理: ARRAY[]::TEXT[], 复杂DEFAULT值

### 2. 双模式运行架构

## 🐛 调试过程记录

### 遇到的5个关键问题及解决方案

#### 问题1: 重复PRIMARY KEY
**错误**: `table has more than one primary key`
**原因**: `BIGSERIAL PRIMARY KEY` → `INTEGER PRIMARY KEY AUTOINCREMENT PRIMARY KEY`
**修复**: 正则匹配 `BIGSERIAL\s+PRIMARY\s+KEY` 整体替换

#### 问题2: SQLite不支持#注释
**错误**: `near "#": syntax error`
**原因**: PG SQL中包含 `# 注释` 行
**修复**: 在注释删除逻辑中加入 `#` 开头行过滤

#### 问题3: 复杂DEFAULT函数
**错误**: `near "(" syntax error` at `datetime('now')`
**原因**: SQLite不允许函数调用作为DEFAULT值（除少数内置函数）
**修复**:
- `datetime('now')` → `CURRENT_TIMESTAMP`
- `uuid_generate_v4()` → `''` (空字符串，应用层填充)
- `lower(hex(randomblob(16)))` → `''`

#### 问题4: JSON格式不匹配
**错误**: `'list' object has no attribute 'get'`
**原因**: product_master.json是 `{"products": {"SKU": {...}}}` 嵌套格式
**修复**: 增加3种格式的自动检测和处理逻辑

#### 问题5: 字段名不匹配
**结果**: 24个产品全部被跳过 (skipped=24)
**原因**: JSON用`sku_code`，代码查找`code/product_code/sku`
**修复**: 将`sku_code`加入优先查找列表

## 💡 关键经验总结

### 技术收获

1. **PG→SQLite语法差异比预期大得多**
   - 不只是类型名称不同，连DEFAULT值、注释、约束都有差异
   - 需要完整的转换引擎而非简单字符串替换

2. **双模式架构的价值**
   - 降低开发门槛（无需装PG）
   - 加速CI/CD（SQLite测试快10倍）
   - 生产环境仍用PG保证性能

3. **数据格式容错的重要性**
   - 真实JSON可能有多种格式
   - 必须支持自动检测和适配
   - 字段名映射需要考虑多种命名习惯

### 工程实践

1. **渐进式调试策略**
   - 先输出转换后SQL检查 → 发现COMMENT/EXTENSION问题
   - 再sqlite3命令行执行 → 发现DEFAULT函数问题
   - 最后Python cursor.execute → 确认所有修复有效

2. **测试脚本的价值**
   - 编写独立验证脚本避免PYTHONPATH反复问题
   - 一次性验证多步流程提高效率
   - 可复用于CI/CD regression test
