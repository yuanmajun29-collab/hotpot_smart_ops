## 📊 现状分析

### 1. Edge UI 当前认证 (PIN模式)

**文件**: `edge/edge-ui/api/auth_api.py` (~276行)

**技术栈**:
- 认证方式: 6位数字 PIN + SHA256 哈希
- 会话管理: Cookie-based Session (`session_token`, HttpOnly)
- 过期策略: 30 分钟滑动窗口超时
- 存储方式: `conf/pin_store.json` (文件) + 内存字典

**API 端点**:
```
POST /api/v1/auth/setup   - 设置初始 PIN (一次性)
POST /api/v1/auth/login   - PIN 登录验证
POST /api/v1/auth/logout  - 登出清除 session
GET  /api/v1/auth/status  - 获取认证状态
```

**数据模型**:
```python
class PinLoginRequest:
    pin: str  # 6位数字

# Session 存储
_active_sessions: Dict[str, dict] = {
    token: {
        "created_at": float,
        "expires_at": float,  # 30分钟后
    }
}
```

**特点**:
✅ 简单易用（适合边缘盒子单用户场景）
✅ 无需用户名密码记忆负担
⚠️ 无角色权限概念（单一 PIN = 全部权限）
⚠️ 内存 session 不支持多实例部署
⚠️ 无法与 Event Hub 的 RBAC 对接

|------|:-------------:|:---------------:|

| **与 Hub 对接** | ❌ 无法对接 | ✅ 原生集成 |

## 🎯 统一方案设计

### 设计原则

1. **以 Event Hub JWT 为标准** — 已有完整实现，无需重复造轮子
2. **Edge UI 从 PIN 平滑迁移到 JWT** — 保持向后兼容
3. **保留 Edge UI 简洁性** — 边缘盒子场景仍支持快速访问
4. **双模式过渡期** — 支持 PIN + JWT 共存（可配置切换）

### 核心组件设计

#### 1. 统一认证模块 (`auth_unified.py`)

**位置**: `hotpot_platform/cloud/event_hub/middleware/auth_unified.py`

**功能**:
```python
class UnifiedAuthManager:
    """统一认证管理器 (PIN + JWT 双模式)"""

    # 配置
    AUTH_MODE: str  # "jwt" | "pin" | "dual" (默认 dual 过渡期)

    # JWT 登录 (复用现有 auth.py)
    async def jwt_login(self, username: str, password: str,
                       store_id: str = None) -> AuthResponse:
        """
        调用 auth.login_user() → 返回 JWT Token
        兼容 Event Hub 现有 12 个 Demo 用户
        """

    # PIN 登录 (迁移自 auth_api.py)
    async def pin_login(self, pin: str) -> AuthResponse:
        """
        验证 PIN → 内部映射为预设用户 → 生成 JWT
        映射规则 (可配置):
          - 默认 PIN "123456" → "zhangdian" (店长)
          - 或读取 pin_user_mapping.json 自定义
        """

    # Token 验证 (统一入口)
    def verify_token(self, token: str) -> Optional[AuthContext]:
        """
        统一验证入口:
        1. 尝试 JWT 解码 (PyJWT)
        2. 如果失败且为 PIN 模式 → 回退到 session 验证
        3. 返回统一的 AuthContext
        """

    # FastAPI 依赖注入
    def get_current_auth(self, request: Request,
                          creds: HTTPAuthorizationCredentials = Depends(bearer)
                         ) -> AuthContext:
        """
        统一认证依赖:
        - 从 Header/Cookie 提取 Token
        - 调用 verify_token()
        - 注入 AuthContext 到 request.state
        """
```

#### 2. PIN → JWT 映射机制

**配置文件**: `conf/pin_jwt_mapping.json` (可选)

```json
{
  "default_pin": "123456",
  "default_user": "zhangdian",
  "mappings": {
    "123456": {"username": "zhangdian", "role": "店长"},
    "654321": {"username": "chushi", "role": "厨师长"},
    "111111": {"username": "quyududao", "role": "区域督导"}
  },
  "allow_custom_pin": true
}
```

**映射逻辑**:
```python
async def pin_login(self, pin: str) -> AuthResponse:
    # 1. 验证 PIN (SHA256 哈希比对)
    if not self._verify_pin_hash(pin):
        raise HTTPException(401, "PIN 错误")

    # 2. 查找映射用户
    user_info = self.pin_mappings.get(pin)

    # 3. 如果没有显式映射 → 使用默认用户
    if not user_info:
        user_info = {"username": self.default_user, "role": "店长"}

    # 4. 调用 JWT 生成逻辑 (复用 auth.create_access_token)
    token = create_access_token(
        username=user_info["username"],
        role=user_info["role"],
        store_id=self.store_id
    )

    return {
        "access_token": token,
        "token_type": "bearer",
        "expires_in": JWT_EXPIRE_HOURS * 3600,
        "login_mode": "pin",  # 标记来源
        "user": {
            "username": user_info["username"],
            "name": user_info.get("username"),
            "role": user_info["role"],
            "store_id": self.store_id,
        }
    }
```

## ⚠️ 风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|:----:|----------|
| **PIN → JWT 映射冲突** | 用户无法登录 | 中 | 提供配置界面自定义映射；Fallback 到默认用户 |
| **双模式代码复杂度** | 维护成本高 | 高 | Phase 3 完全移除 PIN；Phase 1-2 代码注释清晰标注 Legacy |
| **前端 Cookie/LocalStorage 冲突** | Token 丢失 | 低 | 统一使用 localStorage 存储 JWT；Cookie 仅用于 PIN→JWT 过渡期 |
| **性能开销 (JWT 验证)** | API 延迟增加 | 低 | PyJWT 解码 < 1ms；可加 Redis 缓存已解码 Token |
| **向后兼容破坏** | 旧客户端无法使用 | 中 | 保留旧 `/login` 端点 2 个 Sprint；文档通知升级 |
