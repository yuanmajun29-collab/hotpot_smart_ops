## 1. 定位与范围

### 1.1 产品定位

> **内部定位**：「火瞳——冯校长连锁运营中台」
> **技术描述**：「视觉+数据双引擎 AI 运营系统」

**一句话价值**：摄像头看见后厨与前厅异常，数据引擎辅助算清损耗和订货，店长在同一工作台完成确认与复盘。

**完整版**：「摄像头替你看后厨，AI 替你算订货，手机上管所有店。」

看得见的损失（视觉 AI 废料检测）+ 算得清的订货（AI 销量预测+库存优化）+ 管得住的连锁（多店总览+SOP 合规+供应商画像）+ 管得了的冻品（品牌规格锁定+温控追溯+退换货流程）+ 配得上的助理（每个岗位一个 AI 入口）。

### 1.2 三阶段路线

| 阶段 | 目标 | 门槛 |
|------|------|------|
| 当前：两店验证 | 椒江、玉环的真实数据和流程跑通 | 原始 POS、人工核验、店长确认、前后对照 |
| 区域标准化 | 形成浙江新店部署与运营标准 | 两店可复用、数据一致、部署可控 |
| 对外输出 | 向体系内及外部连锁复制 | 真实 ROI、稳定交付与合规定价 |

### 1.3 明确边界

- 火瞳连接 POS、ERP、库存、采购和会员系统，**不取代**它们。
- 火瞳可给出预警、损耗估算和订货建议；正式采购、库存扣减和关键食安处置必须由授权人员确认。
- 当前优先两家自营店，不以外部收费、客户数量或市场规模作为当前阶段验收指标。
- 当前聚焦单一火锅业态；未来可扩展至"火锅+"多业态（火锅+酒吧/火锅+KTV/一人食），但不在当前版本范围内。

### 1.4 竞品差异化定位

> 来源：2026-07-28 市场调研与竞品评估

| 维度 | 百度一见 | Winnow/PreciTaste | ClearCOGS/PAR | 海底捞 KPAD | **火瞳** |
|------|----------|-------------------|---------------|-------------|----------|
| 核心能力 | 视觉巡检 | 视觉废料检测 | 数据预测 | 数据订货 | **双引擎(视觉+数据)** |
| 订货闭环 | 无 | 无 | 有(无视觉) | 有(自研) | **有(视觉→数据→订货→损耗)** |
| 火锅垂直 | 无 | 无 | 无 | 有(自用) | **有(7工位SOP+火锅周期因子+冻品供应链)** |
| 岗位助理 | 无 | 无 | 无 | 有(大明白) | **有(店长/后厨/采购/供应商四角色)** |
| 部署模式 | 利旧设备 | 专用摄像头 | 纯软件 | 自研自用 | **边缘盒子+云服务** |

**一句话差异化**：百度一见做"看见"（视觉巡检），火瞳做"看见+算清+管住"（双引擎闭环）。百度一见告诉你有问题，火瞳还告诉你怎么办。

### 1.5 产品底层设计哲学（三大支柱）

> 火瞳的全部 71 项功能围绕三个底层目标设计：**提高出品率和销量 → 分层管控 → 流程闭环**。这不是功能堆砌，而是一套从食材到利润的完整经营哲学。

#### 支柱一：提高出品率和销量

> **核心逻辑**：出品率每提高 1 个百分点 = 食材成本下降 1 个百分点 = 净利润直接提升。销量每提升 1 桌/天 = 年营收增加约 ¥1.5 万。火瞳从供应链到前厅全链路优化这两个核心指标。

```
┌─────────────────────────────────────────────────────────────────┐
│                提高出品率 × 提高销量 = 增加利润                  │
│                                                                 │
│  出品率提升链（食材→成品转化率）                                │
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐            │
│  │供应链 │→│仓库  │→│粗加工│→│精加工│→│出品  │            │

│  │品牌规格│  │FIFO  │  │SOP   │  │品质  │  │出品率│            │
│  │锁定   │  │临期  │  │合规  │  │检测  │  │统计  │            │
│  │→品质  │  │→减少 │  │→减少 │  │→减少 │  │→提高 │            │

│  └──┬───┘  └──┬───┘  └──┬───┘  └──┬───┘  └──┬───┘            │
│     │         │         │         │         │                  │
│     ▼         ▼         ▼         ▼         ▼                  │
│  K01废料检测→N04损耗金额→N01预测校准→N02采购量调整              │
│  = 每个环节的损失被量化、被追溯、被修正                          │
│                                                                 │
│  销量提升链（更多桌次×更高客单×更高复购）                       │
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐            │
│  │N01   │→│K04   │→│K33   │→│K13   │→│N22   │            │
│  │客流  │  │桌态  │  │主动  │  │翻台  │  │菜品  │            │
│  │预测  │  │检测  │  │服务  │  │分析  │  │推荐  │            │

│  └──────┘  └──────┘  └──────┘  └──────┘  └──────┘            │
│                                                                 │
│  损耗率：12-15%(部署前) → 8%(试点) → 5%(验证) → 3%(成熟)       │
│  出品率：80-85%(部署前) → 88%(试点) → 92%(验证) → 95%(成熟)     │
│  翻台率：1.5-2.0(部署前) → 2.5+(目标)                           │
│  客单价：通过N22菜品推荐提升¥5-10/桌                            │
│  复购率：通过N18会员分析提升                                     │

```

**关键指标**：
- 出品率 = 成品重量 / 原料重量（目标：≥标准阈值，按食材设定）
- 损耗率 = 废料金额 / 采购金额（目标：8%→5%→3%）
- 翻台率 = 日均翻台次数（目标：≥2.5 次）
- 备货偏差率 = |预测-实际| / 实际（目标：≤15%）

**双向数据流的核心目的**：

| 目的 | 自下而上的贡献 | 自上而下的贡献 |
|------|---------------|---------------|
| 降本增效 | 损耗/出品率/周转数据层层上报 | 采购预算/SOP标准/告警阈值层层下达 |
| 节省人力 | AI替代人工采集和分析 | AI助理推送任务，减少人工巡检 |
| 降低浪费 | 废料/临期/过量数据实时上报 | FIFO规则/调拨指令/采购量调整 |
| 流程优化 | 偏差/违规/瓶颈数据上报 | SOP更新/规则调整/参数优化 |
| 利润最大化 | ROI/成本/营收数据提炼 | 利润目标/扩张计划/定价策略 |

#### 支柱三：流程闭环

> **核心逻辑**：传统餐饮管理是"开环"——发现问题但不闭环、有数据但不回流、有标准但不改进。火瞳的每个流程都是闭环：采集→识别→决策→执行→反馈→优化，数据不落地、流程不断链。

```
┌─────────────────────────────────────────────────────────────────┐
│                    火瞳 · 四重流程闭环                           │
│                                                                 │
│  闭环一：业务闭环（采购→销售→补货）                              │
│  N01预测→SC01采购决策→S02验收入库→N21库位→K09工位→             │
│  K31出品→K04就餐→POS销售→N04损耗→N01预测(次日)                 │
│  ↑ 数据不落地，每个环节的输出是下个环节的输入                    │
│                                                                 │
│  闭环二：AI闭环（预测→偏差→回灌→更准）                          │
│  N01预测→实际消耗→N05偏差分析→N17回灌训练→模型更新              │
│  →次日更准的预测→更优的采购→更低的损耗                           │
│  ↑ 越用越准，越准越省                                           │
│                                                                 │
│  闭环三：管理闭环（告警→确认→处理→复盘→改进）                   │
│  K01检测废料→A02推送后厨→人工确认→处理记录→                     │
│  K27 SOP评分→周度复盘→规则调整→下次更少废料                     │
│  ↑ 每次问题都变成规则改进，不重复犯错                            │
│                                                                 │
│  闭环四：品质闭环（供应商→验收→出品→客诉→改进）                 │
│  S01主数据→S02验收→K31出品质检→客诉反馈→                       │
│  N07供应商画像→N08评级调整→S03退换货→供应商改进                 │
│  ↑ 品质问题追溯到供应商，驱动供应链改进                          │
└─────────────────────────────────────────────────────────────────┘
```

**闭环验收标准**（每个闭环必须满足）：
1. 有采集（IoT/视觉/POS 自动采集，不依赖人工录入）
2. 有识别（AI 自动识别异常/偏差/风险）
3. 有决策（AI Agent 生成建议，人工确认后执行）
4. 有反馈（执行结果回写系统，形成数据闭环）
5. 有改进（偏差数据回灌模型/规则，下次更优）

### 1.4 目标与非目标

**目标（做）**：
- 视觉 AI：后厨损耗检测 + SOP 合规 + 出品质检 + 桌态 + 员工行为
- 数据 AI：智能订货预测 + 库存优化 + 供应商画像 + 损耗成本闭环 + AI 运营建议 + 预测自动回灌训练 + 会员数据分析 + AI 菜品推荐
- 冻品供应链：货品主数据管理 + 收货验收 + 退换货流程 + 温控追溯
- 岗位 AI 助理：店长助理 + 后厨助理 + 采购助理 + 供应商协同端 + 知识库助理
- 火锅 Knowhow：7 工位 SOP + 锅底管理 + 效期标签 + 蒸汽适配 + 出品率管控
- IoT 食安：冷柜温度 + 温湿度 + 保质期预警
- 连锁管控：多店总览 + 对比排名 + 合规审计 + 跨店库存调拨
- 部署体验：30 分钟部署 + 硬件订阅

**非目标（不做）**：
- 供应链/ERP 系统（通过 API 对接哗啦啦/客如云/蜀海）
- 会员/CRM 系统 CRUD 和营销触达（预留 API 对接美团/客如云），但做会员消费数据下游分析
- 收银/点餐系统（互补合作，不替代）
- 全自动机器人厨房（辅助而非替代人力）
- 政府明厨亮灶合规（已有摄像头覆盖，不竞争监管场景）

## 2. 用户与工作闭环

### 2.1 用户角色

| 角色 | 主要问题 | 火瞳交付 |
|------|----------|----------|
| 店长 | 今天哪些事情必须处理 | 高优先级待办、原因、动作、结果（A01 店长助理） |
| 后厨负责人 | 备货、报损、SOP 如何纠偏 | 废料事件、品质/SOP 提醒、人工确认（A02 后厨助理） |
| 采购 | 该买多少、供应商是否可靠 | 预测范围、库存风险、采购建议（人工确认）（A03 采购助理） |
| 供应商 | 订单确认、品质反馈、退换货处理 | 订单确认、品质反馈、退换货流程（A04 供应商协同端） |
| 区域运营/总代 | 两店及后续门店哪里异常 | 多店对比、周复盘、标准执行情况 |
| 老板 | 是否改善利润、是否值得复制 | 损耗、缺货、周转、ROI 与复制门槛 |

### 2.2 工作闭环

闭环统一为：**采集事件 → 识别/计算 → 告警或建议 → 人工确认 → 处理结果 → 周度复盘 → 规则改进**。

> 1. **无分区标识**：鸡蛋/调料/汤桶/耗材混放，找货靠记忆（10 秒 → 2 分钟）
> 2. **无库位标签**：每个货架/柜子没有"这里放什么"的可视化标签
> 3. **通道堵塞**：购物车、整箱冻品、杂物挤占通道（紧急情况下无法快速取货）
> 4. **重物超高堆放**：汤桶叠 4-5 层（≈1.5-1.8m），无防倾倒措施（安全隐患）
> 5. **冷冻柜无内部分区**：柜内食材混放，找货需开门逐个翻找（盘库效率低）
> 6. **冷链混放风险**：冷冻食品、保温汤桶、常温耗材同区域，无温度梯度管控

## 4A. 四大场景 AI 深度工作流

> **目标**：通过 IoT 感知 + AI 视觉识别 + AI Agent 决策 + 数字座舱管控，理清和优化供应链、后厨、仓库、前厅四大场景的全流程，实现降本增效、提高出品率、增加企业利润。
>
> **技术分层**：
> - **IoT 感知层**：传感器/电子秤/RFID → 实时数据采集
> - **AI 视觉层**：摄像头+YOLO/CLIP → 行为识别/品质检测/状态判别
> - **AI Agent 层**：预测引擎+规则引擎+大模型 → 智能决策/建议生成/自动告警
> - **数字座舱层**：实时看板+趋势分析+ROI 追踪 → 全局管控/复盘优化

### 6.2 POS 与回测硬规则

- 真实 POS CSV 必须保留 `business_date`、SKU、数量、价格及来源门店。
- 导入前运行 `scripts/validate_pos_history.py`，输出文件 SHA-256、日期覆盖、缺失日和重复记录。
- 回测使用 `scripts/backtest_real_pos_l1.py`；默认要求至少 90 个经营日，报告必须附源文件指纹。
- L1 MAPE ≤45% 才可进入"可用"评估；45%-55% 只能带校准试运行；>55% 不进入订货建议阶段。

- 本 v5.3 是唯一产品主基线；v5.0、v5.2 及早期 PRD 作为历史参考，不再并列指导开发。

- 每次里程碑（M0/M1/M3/M6/M12）完成后更新本文件的功能状态和验收结果。
