## 二、时间可行性

### 2.1 展会倒计时（2026年10月，距今~2个月）

| Sprint | 时间 | 任务 | 工作量 | 可行性 |
|--------|------|------|:------:|:------:|
| D1 | 8月1-2周 | S01货品主数据+S02收货验收+S03退换货 | 3项×5天=15天 | ✅ 可行 |
| D2 | 8月3-4周 | A01店长助理+A02后厨助理+A03采购助理 | 3项×5天=15天 | ⚠️ 紧（Agent框架需先建） |
| R1 | 8月并行 | SQLite→PG + tenant_id + MQTT管道 | 重构3项 | ⚠️ 需与D1/D2并行 |
| D3 | 9月1-2周 | 集成测试+双引擎联调+两店数据联调 | 2周 | 🔴 风险（首次端到端） |
| D4 | 9月3-4周 | Demo彩排+演示脚本+展会物料 | 2周 | ✅ 可行 |
| 缓冲 | 10月1周 | 应急修复+最终彩排 | 1周 | ✅ 缓冲 |

### 2.2 关键路径分析

```
D1(8月1-2周) ──→ D2(8月3-4周) ──→ D3(9月1-2周) ──→ D4(9月3-4周) ──→ 展会(10月)
     │                 │                 │
     │                 │                 └── 关键路径：首次端到端联调
     │                 └── 依赖：Agent框架必须先建（8月第1周）
     └── 依赖：王总货品数据必须8月第1周前录入
```

### 2.3 时间风险

| 风险 | 概率 | 影响 | 应对 |
|------|:----:|:----:|------|
| 王总货品数据未按时录入 | 🔴高 | D1延期 | 8月第1周前必须拿到，否则用模拟数据兜底 |
| Agent框架建设超时 | 🟡中 | D2延期 | 先建最小MVP（规则引擎+推送），LLM增强后补 |
| D3联调发现重大问题 | 🟡中 | D4压缩 | D3预留2周，问题大则砍非核心功能 |
| 展会准备物料延误 | 🟢低 | 展会效果 | 提前2周准备，D4专注彩排 |

### 2.4 时间可行性结论

**总评：时间紧但可行。** 关键路径是 D1→D2→D3→D4，其中 D3（首次端到端联调）风险最高。建议：
1. Agent框架在8月第1周与D1并行启动（最小MVP）
2. R1重构与D1/D2并行，不阻塞功能开发
3. D3预留2周缓冲，发现问题可砍非核心功能
4. 展会Demo策略：真实数据为主+趋势为辅+模拟兜底
