### 0.3 核心设计原则

| # | 原则 | 说明 | 应用 |
|---|------|------|------|
| P1 | **视频不上云** | 隐私保护+带宽节省 | 所有推理在边缘完成 |
| P2 | **双引擎驱动** | 视觉引擎"看见"+数据引擎"算清" | 损耗检测→库存扣减→订货建议闭环 |
| P3 | **渐进式降级** | L1→L2→L3→L4任层失败优雅降级 | 预测/推理/订货全部适用 |
| P4 | **最小侵入扩展** | 不修改已有核心模块 | 新功能通过新增模块+事件订阅实现 |
| P5 | **离线优先** | 断网24h正常工作 | 本地SQLite+断网缓存队列 |
| P6 | **可插拔管线** | 新场景丢文件即可扩展 | 后厨7段+前厅双模式 |
| P7 | **数据闭环** | AI预测→实际消耗→偏差反馈→模型优化 | N17回灌机制 |

# === 领域模型伪代码 ===

class Store:
    """门店"""
    store_id: str
    name: str
    region_id: str                          # 所属区域
    tenant_id: str                          # 租户ID(加盟商)
    config: StoreConfig                     # 门店配置(摄像头/SOP/阈值)

class OpsEvent:
    """运营事件 — 系统核心数据结构"""
    event_id: str                           # UUID
    event_type: str                         # kitchen_waste / table_status / iot_alert ...
    source: str                             # vision / iot / manual / pos / erp
    store_id: str
    timestamp: datetime
    metadata: Dict                          # 类型特定的载荷数据
    confidence: float                       # AI置信度 0-1
    processed: bool                         # 是否已处理

class WasteEvent(OpsEvent):
    """损耗事件 — 视觉引擎产出"""
    sku: str                                # 食材SKU
    waste_type: str                         #过期/变质/加工/顾客剩余
    count: float                            # 数量(盘/份/kg)
    estimated_cost: float                   # 估算成本
    image_url: str                          # 快照URL(本地)

class TableStatusEvent(OpsEvent):
    """桌态事件 — 前厅引擎产出"""
    table_id: str
    status: str                             # empty / dining / needs_clearing
    duration_minutes: int                  # 当前状态持续时长
    guest_count: int                        # 就餐人数

class SalesRecord:
    """销量记录 — 数据引擎输入"""
    store_id: str
    business_date: date
    sku: str
    qty_sold: float
    revenue: float
    hour_dist: Dict[int, int]              # 时段分布

class InventoryMovement:
    """库存变动 — 数据引擎核心"""
    store_id: str
    sku: str
    movement_type: str                     # stock_in / stock_out / waste / adjust
    qty_change: float
    reason: str
    ref_type: str                          # vision / pos / erp / manual
    ref_id: str                            # 关联事件ID

class OrderSuggestion:
    """订货建议 — 数据引擎输出"""
    store_id: str
    sku: str
    suggested_qty: float
    supplier: str
    urgency: str                           # urgent / normal / low
    reason: str                            # 决策理由
    status: str                            # pending / approved / rejected / ordered

### 5.4 核心场景4: 断网降级→恢复同步

**前置条件**: 4G+宽带同时中断

```
t=0      网络中断检测 (heartbeat timeout)
t=0.1s   Edge Agent 进入离线模式
         - 推理继续正常 (本地GPU)
         - 事件写入本地SQLite (store_forward.db)
         - 标记 offline=True

t=0-24h  离线运行 (所有功能正常, 除云端同步)
         - 废料检测 ✅
         - 桌态检测 ✅
         - IoT监控 ✅
         - 本地Dashboard ✅ (LAN访问)
         - 日报生成 ⚠️ (仅本地, 不推送)
         - 订货建议 ⚠️ (仅L1规则基线)

t=24h    若仍离线 → 告警: "断网超过24h, 请检查网络"
         本地存储上限: ~10000条事件 (约3天量)

t=N      网络恢复
t+0.1s  检测到网络
t+1s    启动批量同步:
         - 遍历 store_forward.db 未上传事件
         - 批量POST → Event Hub (每次100条)
         - 上传成功 → 删除本地记录
t+30s~5min 取决于积压量 (通常<1000条, <1分钟同步完)
t+5min   同步完成 → 发送恢复通知
         - 补生成离线期间日报
         - 补推送遗漏告警 (去重)
         - 数据引擎补跑预测
```
