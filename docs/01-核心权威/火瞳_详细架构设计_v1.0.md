#### 1.1.1 Vision Worker（前厅视觉推理）

```
模块路径: edge/front_hall/inference/vision_worker.py
进程模型: 独立进程 (由 edge agent server :9100 管理)
依赖: YOLOv8 (目标检测) + CLIP (图像理解) + OpenCV
```

**核心函数**: `process_camera(store_id, camera, backend, hub, uat_root, out_dir) -> Dict`

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `store_id` | str | ✅ | 门店标识，如 `"store_yuhuan"` |
| `camera` | Dict | ✅ | 摄像头配置（来自 `config.json`） |
| `backend` | str | ✅ | 推理后端：`"plan_a"` / `"plan_b"` |
| `hub` | EdgeHubClient | ✅ | 平台通信客户端 |
| `uat_root` | Path | ✅ | UAT 配置根目录 |
| `out_dir` | Path | Optional | 结果输出目录 |

**返回值结构**:
```python
{
    "store_id": "store_yuhuan",
    "camera_id": "cam_front_01",
    "zone": "front",                    # front / kitchen / warehouse
    "timestamp": "2026-07-29T13:00:00Z",
    "frame_path": "/tmp/ipc_frames/front_20260729_130000.jpg",
    "inference_ms": 38.5,               # 推理耗时(ms)
    "status": "ok",                     # ok / error / skipped
    "detections": [...],                # YOLO 检测结果列表
    "analysis": {                       # 策略分析结果
        "table_states": [...],
        "alerts": [...],
        "recommendation": "..."
    },
    "_diagnostics": {
        "yolo_ms": 25.2,
        "clip_ms": 10.1,
        "total_ms": 38.5,
        "frame_size": [1920, 1080]
    }
}
```

**异常处理**:

| 异常 | 触发条件 | 处理方式 |
|------|----------|----------|
| `FileNotFoundError` | 帧文件不存在 | 记录日志，跳过本轮，继续下一帧 |
| `OSError` | IPC 共享内存不可用 | 重试 3 次，间隔 1s，失败后降级到文件模式 |
| `RuntimeError` | 模型加载失败 | 发送告警事件到 Hub，停止该摄像头推理 |

**四级降级链详情**:

| 级别 | 算法 | 数据需求 | 准确度(MAPE) | 可用性 |
|:----:|------|----------|:------------:|:------:|
| L1 | 移动平均 + 同周环比 | 7 天 | ~18% | ✅ 永远可用 |
| L2 | SARIMA 季节性时序 | 60 天 | ~14% | ⚠️ 需 statsmodels |
| L3 | LightGBM 多因子回归 | 90 天 | ~11% | ⚠️ 需 60+天数据 |
| L4 | LLM 自然语言增强 | 90 天 + LLM | ~10% | ⚠️ 需 LLM API |

#### 1.3.2 OrderAdvisor（订货顾问 N02）

```
模块路径: hotpot_platform/cloud/data_engine/order_advisor.py
三模型混合: EOQ / 报童模型 / 动态安全库存
```

**决策流**:
```
预测需求(N01) → 计算可用库存(N03) → gap = 需求 - 库存 - 在途
→ 按品类保质期选模型:
    · 保质期 > 30天  → EOQ: Q* = √(2DS/H)
    · 保质期 ≤ 3天   → 报童模型: Q* = μ + Z·σ
    · 中间品 4~30天  → 动态安全库存: ROP = d̄·L + Z·σ_L·√L
→ 约束调整(最小起订量/包装单位/供应商MOQ)
→ 生成 OrderSuggestion + 紧急度判定
```

**返回值**: `OrderSuggestion` (见 models.py)

```python
class EdgeHubClient:
    def __init__(
        self,
        hub_url: str,                 # 平台地址, 如 "http://192.168.2.85:8088"
        store_id: str,                # 门店 ID
        api_key: str = "",            # API Key (从环境变量读取)
        queue_db: Optional[Path] = None,  # 离线队列 DB 路径
    ) -> None: ...

    def post(self, path: str, body: Any, *, store_query: bool = True) -> bool:
        """
        POST 请求到 Event Hub。
        失败时自动入队 SQLite 离线队列，网络恢复后自动重发。

        Returns: True=成功/已入队, False=严重错误
        """

    def flush_queue(self) -> int:
        """
        尝试发送离线队列中的所有待发消息。
        Returns: 成功发送数量
        """
```

**重试策略**:

| 场景 | 行为 |
|------|------|

## §3 RESTful API 规范

### 3.1 API 设计原则

1. **RESTful 风格**：资源名词 + HTTP 动词
2. **版本化 URL**：`/api/v1/...` （旧版无前缀，标记 deprecated）
3. **统一响应格式**：所有端点返回 `{ code, data, message }`
4. **分页**：列表接口支持 `?page=1&size=20`
5. **字段选择**：支持 `?fields=id,name,status`
6. **排序**：支持 `?sort=-created_at`（`-` 降序）

### 3.2 认证与授权

#### 认证方式

| 方式 | Header | 适用场景 | 优先级 |
|------|--------|----------|:------:|
| **JWT Bearer** | `Authorization: Bearer <token>` | 用户登录后的操作 | P0 |
| **API Key** | `X-Api-Key: <key>` | 边缘设备/系统集成 | P1 |

#### JWT Token 结构

```json

    "sub": "zhangdian",           // 用户ID
```

## §4 事件驱动协议

### 4.1 事件格式规范

所有事件遵循统一的 `OpsEvent` 结构（见 `common/schemas.py`）：

```python
@dataclass
class OpsEvent:
    event_type: str           # 事件类型标识
    source: str               # vision / iot / pos / system
    level: str                # critical / warn / info
    store_id: str             # 门店 ID
    message: str              # 人类可读描述
    event_id: str = uuid4()   # 全局唯一 ID
    timestamp: str = utc_now() # ISO-8601 UTC
    zone: str = ""            # front / kitchen / warehouse
    table_id: str = ""        # 桌号 (前厅场景)
    confidence: float = 1.0   # 置信度 0~1
    metadata: dict = field(default_factory=dict)  # 扩展元数据
```

### 4.2 事件类型分类

| `kitchen_waste` | warn | 后厨废料检测 | items[{sku, count, weight_kg}] |

| `kitchen_no_mask` | warn | 未戴口罩 | staff_id, zone |

### 4.3 事件路由规则

Event Hub 内部路由矩阵：

| 事件源 | → 消费者 | 处理动作 |
|--------|----------|----------|
| vision_detection | TableStateTracker | 更新桌态 |
| vision_detection | WasteEstimator | 废料估算 |
| iot_temp_abnormal | ColdChainMonitor | 冷链告警 |
| iot_weight_short | LossRiskScorer | 损耗风险评分 |

| * (全部) | DataEngineSubscriber | 数据引擎消费(可选) |

### 4.4 边缘→平台上报协议

**协议**: HTTPS POST (JSON)
**Content-Type**: `application/json`
**认证**: `X-Api-Key` Header

**上报流程**:
```
边缘采集 → 本地预处理 → EdgeHubClient.post()
    ├── 网络正常 → HTTP POST → Event Hub → 200 OK ✅
    └── 网络异常 → SQLite 入队 → 后台 flush → 恢复后重发 ✅
```

**批量上报优化** (边缘侧):
- 视觉事件: 每 10 秒批量聚合（最多 5 帧/批）
- IoT 读数: 每 30 秒批量上报（最多 50 条/批）
- 紧急事件 (critical): 立即上报，不等待批量

### 4.5 离线队列与重试

**离线队列实现**: `common/hub_client.py` → SQLite `pending` 表

**重试配置**:

| 参数 | 值 | 说明 |
|------|:---:|------|
| 最大队列深度 | 1000 条 | 超出后丢弃最旧 |
| Flush 间隔 | 30 秒 | 后台线程定时尝试 |
| 单次 Flush 上限 | 50 条 | 防止风暴 |
| HTTP 超时 | 5 秒 | 单次请求超时 |
| 最大重试次数 | 3 次 | 每条消息 |
| 重试退避 | 指数退避 | 1s → 2s → 4s |
| 过期清理 | 24 小时 | 超时未发送则删除 |
