## 1. 概述

### 1.1 功能定位

货品主数据管理是**冻品供应链（D1）的核心基础模块**，负责统一管理所有供货产品的名称、规格、品牌、价格，形成电子版下单标准。

### 1.2 业务价值

| 利益相关方 | 价值 |
|-----------|------|
| **曹总（统一下单标准）** | 统一SKU编码体系，避免"一物多名"导致采购混乱 |
| **潘厨（品质管控）** | 规格变更需审批，防止供应商私自换品牌 |
| **店长（运营决策）** | 标准化价格体系，支持成本核算和损耗分析 |
| **供应商（王总）** | 明确供货标准，减少因规格争议导致的退换货 |

### 1.3 设计原则

1. **单一数据源 (SSOT)**：所有产品信息以 `ProductMaster` 为准
2. **变更可追溯**：关键字段修改必须走变更申请流程
3. **锁定保护机制**：已锁定的货品标准不可直接修改
4. **轻量持久化**：Edge UI 采用 JSON 文件存储（适合单门店场景）

## 3. 状态机设计

### 3.1 货品生命周期状态机

```
                    ┌──────────────────────────────────────────┐
                    │                                          │
                    ▼                                          │
   ┌───────┐  创建   ┌───────┐  提交审批  ┌───────────────┐   │
   │ 不存在 │ ──────► │ draft │ ────────► │pending_approval│   │
   └───────┘        └───┬───┘            └───────┬───────┘   │
                        │                        │           │
                        │ 通过                   │ 通过       │
                        ▼                        ▼           │
                   ┌─────────┐            ┌──────────┐      │
                   │  active  │◄───────────│  locked  │      │
                   └────┬────┘            └────┬─────┘      │
                        │                      │            │
                  停用/下架               解锁(管理员)       │
                        ▼                      │            │
                   ┌──────────┐                │            │
                   │discontinued│◄─────────────┘            │
                   └─────┬────┘                             │
                         │  重新激活                         │
                         └──────────────────────────────────┘
```

### 3.2 状态转换规则

| 当前状态 | 目标状态 | 触发条件 | 权限要求 |
|----------|----------|----------|----------|
| *不存在* | `draft` | 创建新货品 | 任意认证用户 |
| `draft` | `draft` | 修改非锁定字段 | 创建者/管理员 |
| `draft` | `active` | 直接激活（无需审批） | 管理员 |
| `draft` | *删除* | 删除操作 | 创建者/管理员 |
| `active` | `locked` | 锁定操作 | 管理员 |
| `locked` | `active` | 解锁操作 | 管理员（需填写原因） |
| `active` | `discontinued` | 停用申请 + 审批通过 | 任意用户申请，潘厨/曹总审批 |
| `discontinued` | `active` | 重新激活申请 + 审批通过 | 任意用户申请，潘厨/曹总审批 |
| `active`/`locked` | *关键字段修改* | 变更申请 + 审批通过 | 任意用户申请，潘厨/曹总审批 |

### 3.3 变更申请状态机

```
  ┌──────────┐   审批通过   ┌──────────┐
  │ pending  │ ──────────► │ approved │
  └────┬─────┘             └──────────┘
       │
       │ 审批驳回
       ▼
  ┌──────────┐
  │ rejected │
  └──────────┘
       │
       │ 取消（申请人）
       ▼
  ┌───────────┐
  │ cancelled  │
  └───────────┘
```

#### 4.2.4 PUT /api/v1/products/{sku_code} — 更新货品

**请求体** (`ProductUpdateRequest`) — 所有字段可选：

```json
{
  "unit_price": 135.0,
  "tags": ["热销", "促销"],
  "min_stock_qty": 10.0
}
```

**业务逻辑**:
1. 如果货品**未锁定**：允许修改所有字段
2. 如果货品**已锁定**：仅允许修改非关键字段（unit/tags/location/storage_area/min_stock_qty等）
3. 尝试修改锁定关键字段时返回 `403 Forbidden`

**错误码**:
- `404 Not Found`: SKU不存在
- `403 Forbidden`: 无权修改（锁定保护）
- `500 Internal Server Error`: 服务器内部错误

## 5. 业务规则汇总

### 5.1 锁定保护机制

```
锁定前 (locked=false):
  ├── 可修改: 所有字段
  └── 操作者: 任意认证用户

锁定后 (locked=true):
  ├── 🔒 不可修改: sku_code, name, specification, brand, unit_price
  ├── ✅ 可修改: unit, category, supplier_*, location_*, storage_area, tags, status
  └── 操作者: 管理员（解锁需要）
```

### 5.2 删除保护机制

```
可删除条件 (全部满足):
  ✅ status == "draft"
  ✅ 操作者为创建者或管理员

不可删除情况:
  ❌ status == "active"     → 需先停用(discontinue)
  ❌ status == "locked"     → 需先解锁
  ❌ status == "discontinued" → 历史保留，不物理删除
```

### 5.3 SKU 编码规范

```
格式: FP-{品类缩写}-{序号}

示例:
  FP-MW-001  → Frozen Product - Meat Wool - 001 (毛肚)
  FP-HB-002  → Frozen Product - Hotpot Base - 002 (锅底)
  FP-VC-003  → Frozen Product - Vegetable - 003 (素菜)

品类缩写:
  MW = Meat Wool (毛肚类)
  HB = Hotpot Base (锅底)
  VC = Vegetable (素菜)
  ST = Staple (主食)
  DK = Drink (酒水)
  SN = Seasoning (调料)
```

### 5.4 数据持久化策略

```
存储方式: JSON 文件 (Edge UI 轻量模式)

文件路径: edge/edge-ui/data/product_master.json

文件结构:
{
  "products": {
    "FP-MW-001": { /* ProductMaster 对象 */ },
    "FP-MW-002": { /* ProductMaster 对象 */ }
  },
  "categories": [
    { /* ProductCategory 对象 */ }
  ],
  "change_requests": [
    { /* ChangeRequest 对象 */ }
  ]
}

写入时机:
  - CRUD 操作完成后立即保存 (_save_to_json)
  - 启动时加载 (_load_from_json)

备份建议:
  - 每日自动备份到 data/product_master.json.bak
  - 保留最近7天的备份
```

## 8. 安全考虑

### 8.1 认证与授权

| 层级 | 机制 | 实现 |
|------|------|------|
| **L2 PIN认证** | 6位数字PIN + Session | `Depends(get_current_session)` 注入所有端点 |
| **会话管理** | 服务端Session + Cookie | 登录后返回session_id |
| **权限分级** | 基于角色的隐式控制 | 锁定/解锁/删除仅管理员可操作 |

### 8.2 输入验证

- **Pydantic模型校验**: 所有请求体经过类型/范围/格式验证
- **SQL注入防护**: 使用JSON文件存储，无SQL
- **XSS防护**: FastAPI自动转义JSON响应
- **CSRF防护**: 同源策略（Edge UI为局域网应用）

### 8.3 审计追踪

每个写操作自动记录：
- `created_by` / `updated_by`: 操作人ID
- `created_at` / `updated_at`: 操作时间戳
- `version`: 数据版本号（每次修改自增）
