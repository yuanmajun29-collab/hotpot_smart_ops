## 1. 概述

### 1.1 功能定位

采购订单管理是**冻品供应链（D1）的核心交易模块**，负责：
1. **订单创建**：基于货品主数据(S01)选择SKU，生成采购订单
2. **订单审批**：店长/曹总确认采购内容和金额
3. **供应商确认**：供应商确认可供货（或直接跳过进入待收货）
4. **收货联动**：到货时S02收货质检通过 `po_number` 关联到本订单
5. **订单闭环**：全部/部分收货后自动更新订单状态
6. **退换货触发**：S02质检拒收时自动关联本订单发起退换货

### 1.2 业务价值

| 利益相关方 | 价值 |
|-----------|------|
| **曹总（统一下单标准）** | 标准化采购流程，每笔订单有据可查 |
| **店长（运营决策）** | 实时查看采购进度和到货状态 |
| **潘厨（品质管控）** | 收货时可直接追溯到对应采购订单 |
| **供应商（王总）** | 明确的订货需求，减少沟通误差 |

### 1.3 核心场景（用户故事）

```
作为 店长/采购员
我想要 基于货品主数据创建采购订单并选择供应商
以便于 统一管理采购需求和跟踪到货状态

作为 曹总（统一下单标准）
我想要 审核每笔采购订单的金额和品类合理性
以便于 控制采购成本并确保符合门店标准

作为 潘厨（品质管控）
我想要 在收货质检时看到对应的采购订单信息
以便于 核对实收与订购是否一致

作为 店长
我想要 查看采购订单的执行状态和收货完成率
以便于 评估供应链效率并优化订货策略
```

### 1.4 设计原则

1. **主数据驱动**：订单行项目必须引用S01 ProductMaster的SKU，保证数据一致性
2. **状态机管控**：严格的状态流转，防止非法操作
3. **收货闭环**：通过 `po_number` 与S02收货记录双向关联
4. **离线可用**：Edge UI 本地JSON存储，断网不影响下单操作
5. **渐进增强**：MVP阶段供应商确认为手动，后续可接入协同群(N20)

### 2.2 核心实体详解

#### 2.2.1 PurchaseOrder（采购订单）

| 字段名 | 类型 | 约束 | 说明 | 可变性 |
|--------|------|------|------|--------|
| `po_number` | string(32) | PK, 自动生成 | 格式 `PO-YYYYMMDD-XXXX` | 创建后不可改 |
| `store_id` | string | 必填 | 门店ID（如 "store-jiaojiang"） | 创建后不可改 |

| `supplier` | string? | 可选 | 主要供应商名称 | draft可改 |
| `delivery_address` | string? | 可选 | 送货地址 | 任意状态可编辑 |
| `expected_date` | date? | 可选 | 期望到货日期 | draft/submitted可改 |
| `notes` | string? | 可选 | 订单备注 | 任意状态可编辑 |
| `confirmed_by` | string? | 自动 | 确认人 | 系统维护 |
| `confirmed_at` | datetime? | 自动 | 确认时间 | 系统维护 |
| `received_by` | string? | 自动 | 收货确认人 | 系统维护 |
| `received_at` | datetime? | 自动 | 收货完成时间 | 系统维护 |

| `cancelled_at` | datetime? | 自动 | 取消时间 | 系统维护 |

#### 2.2.2 PurchaseOrderItem（采购订单行项）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `sku` | string | 必填, FK→ProductMaster | SKU编码 |
| `sku_name` | string? | 自动填充 | SKU名称（冗余，方便展示） |
| `quantity` | float | >0 | 采购数量（kg/件） |
| `unit` | string | 默认从ProductMaster获取 | 计量单位 |
| `unit_price` | float | ≥0, 默认从ProductMaster获取 | 单价（元） |
| `amount` | float | 自动计算 | 小计 = quantity × unit_price |
| `supplier` | string? | 可选 | 指定供应商（覆盖订单级supplier） |
| `expected_date` | date? | 可选 | 期望到货日（覆盖订单级） |
| `notes` | string? | 可选 | 行备注 |
| `received_qty` | float | 默认0 | 已收货数量（S02收货时回写） |

### 2.3 枚举定义

```python
class POStatus(str, Enum):
    """采购订单状态"""
    DRAFT = "draft"              # 草稿 - 编辑中
    SUBMITTED = "submitted"      # 已提交 - 待确认

    PARTIAL_RECEIVED = "partial" # 部分收货
    RECEIVED = "received"        # 全部收货
    CANCELLED = "cancelled"      # 已取消
```

## 3. 状态机设计

### 3.1 采购订单状态机

```
                        ┌─────────────────────────────────────────┐
                        │                                         │
                        ▼                                         │
┌───────┐   submit   ┌──────────┐  confirm  ┌──────────┐        │
│ draft │────────────►│ submitted │──────────►│ confirmed │        │
└───┬───┘            └────┬─────┘           └─────┬────┘        │
    │                      │                       │             │
    │ cancel               │ cancel                │ receive     │
    │                      │                       │ (全部到货)   │
    ▼                      ▼                       ▼             │
┌─────────────┐     ┌─────────────┐        ┌─────────────┐       │
│  cancelled  │     │  cancelled  │        │  received   │◄──────┘
└─────────────┘     └─────────────┘        └─────────────┘
                                                 │
                                           receive
                                           (部分到货)
                                                 │
                                                 ▼
                                          ┌─────────────┐
                                          │ partial_recv │
                                          └──────┬──────┘
                                                 │
                                           receive (剩余)
                                                 │
                                                 ▼
                                          ┌─────────────┐
                                          │  received   │
                                          └─────────────┘
```

### 3.2 状态转换规则

| 当前状态 | 操作 | 目标状态 | 前置条件 | 触发角色 |
|---------|------|---------|---------|---------|
| `draft` | submit | `submitted` | items≥1, total_amount>0 | 店长/采购员 |
| `draft` | cancel | `cancelled` | cancel_reason必填 | 店长/采购员 |
| `submitted` | confirm | `confirmed` | — | 曹总/店长 |
| `submitted` | cancel | `cancelled` | cancel_reason必填 | 曹总/店长 |
| `submitted` | return_draft | `draft` | — | 曹总/店长 |
| `confirmed` | receive(all) | `received` | 所有item.received_qty ≥ quantity | 收货员+潘厨(S02审批后) |
| `confirmed` | receive(partial) | `partial` | 部分item有收货 | 收货员+潘厨 |
| `partial` | receive(剩余) | `received` | 所有item收齐 | 收货员+潘厨 |
| `confirmed` | cancel | `cancelled` | 尚未开始收货 | 曹总/店长 |
| `partial` / `received` | — | — | 终态，不可变更 | — |
| `cancelled` | — | — | 终态，不可变更 | — |

### 3.3 与S02收货质检的联动

```
采购订单(S03)                    收货质检(S02)
┌─────────────────┐              ┌─────────────────┐
│ PO-20260801-001 │──po_number──►│ RC-20260801-001 │
│ status:confirmed │              │ status:approved │
│ items:          │              │ items:          │
│  FP-MW-001 ×10kg│◄────匹配────│ FP-MW-001 ×10kg │
│  FP-NB-003 ×5kg │  (sku+qty)  │ FP-NB-003 ×4.9kg│
└────────┬────────┘              └────────┬────────┘
         │                                │
         │  S02审批通过后                   │  po_number回写
         │  自动更新PO状态                 │
         └──────────────►                 │
                   更新 received_qty       │
                   判断 full/partial        │
```

**联动规则（BR-12）**：
- S02收货记录创建时若填写了 `po_number`，系统自动匹配对应PO的行项目
- S02审批通过(approved)后，自动将该收货数量累加到PO行项目的 `received_qty`
- 当所有行项目 `received_qty >= quantity` 时，PO状态自动变为 `received`
- 当部分行项目有收货但未全收齐时，PO状态变为 `partial`

## 4. 业务规则（BR-01 ~ BR-14）

### 4.1 订单创建规则

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| BR-01 | 订单至少包含1个行项目（items.length ≥ 1） | **P0** |
| BR-02 | 每个行项目的SKU必须存在于ProductMaster中（S01校验） | **P0** |
| BR-03 | 每个行项目的quantity必须 > 0 | **P0** |
| BR-04 | 单价优先取行项目指定值，否则取ProductMaster.unit_price | P1 |
| BR-05 | amount = quantity × unit_price（系统自动计算，不允许手动修改） | **P0** |
| BR-06 | total_amount = Σ(items.amount)（系统自动计算） | **P0** |
| BR-07 | po_number格式为 `PO-YYYYMMDD-XXXX`（日期+4位序号） | P1 |

### 4.2 状态流转规则

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| BR-08 | 只有 `draft` 状态可以编辑订单内容（items/supplier/delivery_address） | **P0** |
| BR-09 | 只有 `draft` 和 `submitted` 状态可以取消订单 | **P0** |
| BR-10 | `confirmed` 状态只有在没有关联收货记录时可取消 | **P0** |
| BR-11 | 已 `received` / `partial` 的订单不可取消 | **P0** |

### 4.3 收货联动规则

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| BR-12 | S02收货审批通过后自动回写PO的received_qty并更新状态 | **P0** |
| BR-13 | 同一PO可关联多条收货记录（分批到货场景） | P1 |
| BR-14 | PO金额统计以原始订购金额为准，不因短重而调整（短重在S02处理） | P2 |
