# ADR-002: Edge 本地写入隔离与 Hub 主写约定

> **状态**: 已批准 (2026-08-04)
> **关联**: 整改方案 v1.0 §四.P0-1 · 差距矩阵 P0-1 (65%→目标85%)
> **影响范围**: edge/, hotpot_platform/cloud/, common/

---

## 一、背景与问题

当前 D1-D3 业务接口同时存在两条数据写入路径：

| 路径 | 写入位置 | 认证 | 审计 | 使用场景 |
|------|---------|------|------|---------|
| **Edge 本地** | JSON 文件 / SQLite | PIN 或无 | JSONL 本地日志 | 旧 demo 模式 |
| **Hub 云端** | PostgreSQL | JWT + RBAC | PG 审计表 | 生产模式 |

双轨并存导致：
1. 数据不一致（本地与云端可能冲突）
2. 审计碎片化（无法统一查询）
3. 权限绕过（Edge 本地路径无 RBAC）

## 二、决策

### 2.1 写入权限分层

```
┌─────────────────────────────────────────────────────┐
│                Edge 本地可写 (L1)                    │
│  ✓ 设备配置 (网络/摄像头/IoT/模型/阈值)              │
│  ✓ 设备状态 (心跳/健康度/最后在线)                    │
│  ✓ 离线队列 (断网时事件暂存)                         │
│  ✓ 临时推理结果 (帧级缓存, 不持久化业务数据)          │
├─────────────────────────────────────────────────────┤
│              Hub 云端主写 (L2) ★ 全部业务数据         │
│  ✓ 任务 (清台/采购/收货/SOP)                        │
│  ✓ 事件 (AI检测/IoT/业务操作)                       │
│  ✓ 主数据 (货品/供应商/门店/员工/菜品)               │
│  ✓ 审计日志 (全部操作的 PG审计追踪)                   │
│  ✓ 审批流 (采购审批/任务复核)                        │
│  ✓ 告警与推送                                       │
└─────────────────────────────────────────────────────┘
```

### 2.2 约定规则

**规则 E1**: Edge UI (`edge-ui/`) 仅作为 **配置客户端 + 业务展示面**
- 配置变更 → 写入本地 config YAML / 调用 Hub `/v1/devices/{id}/config`
- **禁止**: Edge UI 直接创建/修改任务、事件、主数据

**规则 E2**: Edge 推理模块 (`edge/*/inference/`) 结果必须上报 Hub
- 检测结果 → `EdgeHubClient.post("/v1/events/ingest", ...)`
- 自动任务 → `EdgeHubClient.post("/v1/tasks/ingest", ...)`
- **禁止**: 推理模块直接写本地 JSON 作为业务数据源

**规则 E3**: `SupplyChainManager` (Edge 本地) 仅用于 **离线降级**
- 正常模式: 所有读写走 Hub API + JWT
- 断网模式: 降级到本地 SQLite + 离线队列
- 恢复后: `data_sync` 模块批量回传，然后标记本地为「已同步」

**规则 E4**: 新功能开发默认走 Hub 路径
- 新增 API 必须先在 `hotpot_platform/` (Hub) 实现
- Edge 本地路径仅作为已有遗留代码的兼容层，标注 `# TODO: 迁移至 Hub`

## 三、当前需迁移的模块

| 模块 | 当前路径 | 目标状态 | 优先级 | 预估工时 |
|------|---------|---------|--------|---------|
| 清台任务 | Hub ✅ 已走通 | 无需迁移 | — | — |
| 采购建议 | `supply_chain.py` 本地+Hub 双轨 | 统一 Hub | P0 | 0.5d |
| 收货记录 | Mock 固定结果 | Hub VLM 桥接 | P1 | 1d |
| 供应商评分 | 本地计算 | Hub 定时任务 | P1 | 0.5d |
| 库存台账 | `inventory_book.py` 本地 | Hub PG 主表 | P1 | 1d |

## 四、数据同步策略 (data_sync)

```
Edge 离线队列 (SQLite)
    │
    │  [网络恢复 / 定时触发]
    ▼
data_sync.push_pending()
    │
    ├─ POST /v1/events/batch   (幂等 key)
    ├─ POST /v1/tasks/batch     (幂等 key)
    └─ POST /v1/audit/log       (只追加)
    │
    │  [Hub 返回 200]
    ▼
标记本地记录 status='synced'
```

**冲突解决**: 以 Hub 时间戳为准（Hub-as-source-of-truth）。本地仅在网络完全不可用时接受写入，恢复后 Hub 版本覆盖本地。

## 五、验收标准

- [ ] Edge UI (`edge-ui/`) 无直接业务数据写入 SQL/JSON 的代码路径
- [ ] 所有新测试用例使用 Hub mock server 而非本地 SupplyChainManager
- [ ] `data_sync.push_pending()` 有对应测试覆盖
- [ ] CLAUDE.md 「已实现模块」标注每个模块的数据写入路径 (L1/L2)
