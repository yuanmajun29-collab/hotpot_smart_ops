## 1. 概述

### 1.1 功能定位

收货质检是**冻品供应链（D1）的核心风控模块**，负责在供应商送货到店时执行：
1. **收货登记**：记录每批到货的SKU、数量、批次信息
2. **VLM视觉质检**：通过视觉大模型分析拍照图片，检测外观缺陷、以劣充好
3. **称重核验**：对比订单量与实收量，计算短重率
4. **潘厨审批**：品质管控人（潘总）审核质检结果，决定通过/拒收

### 1.2 业务价值

| 利益相关方 | 价值 |
|-----------|------|
| **潘厨（潘总/品质管控）** | 通过VLM辅助+人工审核双保险，把控进货品质 |
| **收货员** | 标准化收货流程，拍照留证，减少争议 |
| **供应商（王总）** | 公正透明的质检标准，拒收有据可依 |
| **店长（运营决策）** | 供应商品质数据积累，支持供应商评级(N07/N08) |

### 1.3 核心场景（用户故事）

```
作为 收货员
我想要 在收货时拍照并记录每项货品的实收数量
以便于 系统自动比对订单量并触发质检流程

作为 潘厨（品质管控）
我想要 审核每次收货的VLM质检结果和短重情况
以便于 决定是否通过或拒收该批货物

作为 店长
我想要 查看历史收货记录和供应商的品质趋势
以便于 评估供应商表现并优化采购决策
```

### 1.4 设计原则

1. **双引擎协同**：视觉AI(VLM) + 数据引擎(规则校验) 双重质检
2. **审批可追溯**：所有质检操作留痕，支持审计追溯
3. **离线可用**：Edge UI 本地存储，断网不影响收货操作
4. **渐进增强**：MVP阶段VLM可为Mock，后续接入真实推理

### 2.3 枚举定义

```python
# 收货记录状态机
class ReceivingStatus(str, Enum):
    PENDING = "pending"          # 待质检（收货员已提交）
    INSPECTING = "inspecting"    # 质检中（VLM分析进行中）
    PENDING_APPROVAL = "pending_approval"  # 待潘厨审批
    APPROVED = "approved"        # 已通过（可入库）
    PARTIAL = "partial"          # 部分通过（部分品项拒收）
    REJECTED = "rejected"        # 已拒收（整批退回）

# 品质等级
class QualityGrade(str, Enum):
    A = "A"   # 优秀 — 无缺陷，短重<3%
    B = "B"   # 良好 — 轻微外观问题，短重3-7%
    C = "C"   # 合格 — 明显缺陷或短重7-15%，需关注
    D = "D"   # 拒收 — 严重问题或短重>15%

# 照片类型
class PhotoType(str, Enum):
    OVERVIEW = "overview"        # 全景照（整批货物）
    ITEM_DETAIL = "item_detail"  # 单品特写
    WEIGHT_SCALE = "weight_scale"# 称重照片（带电子秤读数）
    DEFECT = "defect"            # 缺陷照片（有问题时拍摄）
    PACKAGE_LABEL = "package_label"  # 包装标签（批次信息）
```

### 3.2 状态流转规则

| 当前状态 | 目标状态 | 触发条件 | 执行角色 | 权限要求 |
|----------|----------|----------|----------|----------|
| `draft` | `pending` | 收货员提交收货单 | 收货员 | 登录用户 |
| `pending` | `inspecting` | 系统自动触发VLM分析 | 系统 | 自动 |
| `inspecting` | `pending_approval` | VLM分析完成 | 系统 | 自动 |
| `pending_approval` | `approved` | 潘厨点击"全部通过" | 潘厨 | PIN认证 |
| `pending_approval` | `partial` | 潘厨"部分通过"+填写原因 | 潘厨 | PIN认证 |
| `pending_approval` | `rejected` | 潘厨点击"整批拒收"+填写原因 | 梯厨 | PIN认证 |
| `pending_approval` | `draft` | 潘厨"退回修改"（信息不全） | 潘厨 | PIN认证 |
| `approved/partial/rejected` | *(终态)* | 不可变更 | - | - |

### 3.3 自动化规则（系统触发）

| 规则ID | 触发条件 | 动作 | 说明 |
|--------|----------|------|------|
| AUTO-001 | status=`pending` 且 有照片 | 自动进入 `inspecting` | 触发VLM分析 |
| AUTO-002 | VLM分析完成 | 自动进入 `pending_approval` | 通知潘厨审批 |
| AUTO-003 | 所有 item.grade ∈ {A,B} | 建议 `approved` | 系统推荐 |
| AUTO-004 | 任一 item.grade = D | 强制人工审核 | 不能自动通过 |
| AUTO-005 | weight_variance_pct > 15% | 自动标记 grade=D | 短重超阈值 |
| AUTO-006 | temperature_on_arrival > -12°C | 标记 temperature_ok=False | 温度异常告警 |

#### 4.2.2 POST `/api/receiving/records/{record_id}/inspect` — 触发VLM质检

**请求体**:
```json
{
  "use_vlm": true,
  "photo_indices": [0, 1, 2]  // 使用哪些照片进行分析
}
```

**响应** (202 Accepted):
```json
{
  "success": true,
  "message": "VLM质检已启动，预计耗时10-30秒",
  "inspection_id": "INS-20260801-0001",
  "status": "inspecting"
}
```

**VLM分析流程（内部）**:
```
1. 加载照片 → 预处理（resize to 1024x1024）
2. 调用 VLM Bridge API (/api/vlm/analyze)
   ├── 输入: image + prompt("请检查此冻品的外观品质...")
   ├── 输出: JSON { defects: [], quality_score: 0.92, description: "..." }
3. 对每个 photo_type=item_detail 的照片逐张分析
4. 聚合结果 → 生成 QualityCheckResult 列表
5. 应用规则引擎 (AUTO-003 ~ AUTO-006)
6. 写入 quality_results 字段
7. 状态流转: inspecting → pending_approval
```

**VLM Mock模式**（展会Demo用）:

### 5.1 VLM Bridge 接口定义

```

  4. 输入PIN确认 → 完成
```

## 7. 业务规则汇总

| 规则ID | 名称 | 描述 | 严重级别 |
|--------|------|------|----------|
| BR-01 | 供应商校验 | 供应商必须在SupplierInfo中存在 | ERROR |
| BR-02 | SKU有效性 | 收货SKU必须是active状态的ProductMaster | ERROR |
| BR-03 | 实收量为正 | received_qty > 0 | ERROR |
| BR-04 | 短重率计算 | variance = (ordered - received) / ordered × 100 | INFO |
| BR-05 | 短重预警 | variance > 15% 时标记为"需重点关注" | WARNING |
| BR-06 | 状态校验 | 审批操作仅在 pending_approval 状态有效 | ERROR |
| BR-07 | D级阻断 | 存在grade=D品项时不允许"全部通过" | ERROR |
| BR-08 | 入库联动 | 审批通过后触发库存入库(N03) | INFO |
| BR-09 | 供应商画像 | 审批结果写入供应商评分(N07) | INFO |
| BR-10 | 温度校验 | 冻品到货温度应 ≤ -12°C | WARNING |
| BR-11 | 批次追溯 | batch_id + production_date + expiry_date 必须配套 | WARNING |
| BR-12 | 照片最低要求 | 提交质检前至少1张全景照 | WARNING |
| BR-13 | 退回权限 | 仅潘厨角色可执行退回修改操作 | ERROR |
| BR-14 | 自审回避 | 收货人与审批人不能为同一人 | WARNING |
