## 1. 概述

### 1.1 功能定位

供应商协同与评分是**冻品供应链（D1）的最后一环**，完成"品质闭环四"：
```
S01主数据 → S02验收 → K31出品质检 → 客诉反馈 → N07供应商画像 → N08评级调整 → S03退换货 → 供应商改进
```

本模块负责：
1. **供应商档案管理**：维护供应商基本信息、资质、供应SKU范围
2. **多维度评分引擎**：基于S02质检数据+S03订单数据，自动计算供应商综合评分
3. **状态生命周期**：准入审核 → 活跃合作 → 观察期 → 停用/拉黑
4. **协同工作流**：询价记录、对账单、品质反馈通知

### 1.2 业务价值

| 利益相关方 | 价值 |
|-----------|------|
| **潘厨（潘总）** | 统一管理所有供应商档案，基于数据客观评分，不再凭感觉判断 |
| **店长** | 一眼看到哪些供应商靠谱、哪些有风险，辅助采购决策 |
| **王总（供应商）** | 公正透明的评分标准，知道自己在哪方面需要改进 |
| **曹总（统一下单标准）** | 根据供应商评分制定采购策略，优化供应链结构 |

### 1.3 核心场景（用户故事）

```
作为 潘厨（品质管控）
我想要 维护供应商档案并查看每个供应商的评分详情
以便于 基于数据做出准入/淘汰决策

作为 店长
我想要 看到所有供应商的评分排名和趋势变化
以便于 选择最优供应商并识别风险供应商

作为 采购人员
我想要 在创建采购订单时看到供应商推荐和比价
以便于 降低采购成本同时保证品质

作为 系统（自动化）
我想要 在每次收货质检完成后自动更新供应商评分
以便于 评分始终反映最新表现
```

### 1.4 设计原则

1. **数据驱动评分**：评分完全来自S02质检+S03订单的客观数据，不依赖人工主观打分
2. **闭环联动**：S02审批通过→自动触发评分重算→可能触发等级变更通知
3. **渐进式淘汰**：不直接拉黑，而是 active → probation → suspended → blacklisted 的渐进流程
4. **供应商视角友好**：A04供应商端可查看自己的评分和改进建议

## 3. 评分体系设计

### 3.1 四维评分模型

```
                    ┌─────────────────────────┐
                    │    综合评分 (overall)     │
                    │  = Σ(维度分 × 权重) + 调整 │
                    └────────────┬──────────────┘
                                 │
        ┌────────────────────────┼────────────────────────┐
        │                        │                        │
   ┌────▼────┐            ┌─────▼─────┐           ┌──────▼──────┐
   │ 质量 40% │            │  交付 25%  │           │   价格 20%   │
   │─────────│            │───────────│           │─────────────│
   │ 数据来源:│            │ 数据来源:  │           │ 数据来源:    │
   │ S02质检  │            │ S03订单    │           │ S03订单单价  │
   │          │            │ + S02收货  │           │ vs 标准价    │
   │ 指标:    │            │            │           │              │
   │ ·拒收率  │            │ 指标:      │           │ 指标:        │
   │ ·平均等级 │            │ ·准时率    │           │ ·价格竞争力  │
   │ ·D级次数  │            │ ·平均交货周期│           │ ·价格稳定性  │
   └─────────┘            └───────────┘           └──────────────┘
                                                        │
                                                ┌───────▼───────┐
                                                │   服务 15%     │
                                                │───────────────│
                                                │ 数据来源:      │
                                                │ 人工评价+退换货 │
                                                │ 指标:          │
                                                │ ·响应速度      │
                                                │ ·配合度        │
                                                └───────────────┘
```

### 3.2 评分算法详解

#### 3.2.1 质量分 (quality_score, 权重 40%)

```python
def calc_quality_score(supplier_data):
    """
    基于S02收货质检数据计算质量分

    输入:
      - rejection_rate: 拒收率 (0~1)
      - avg_grade_avg: 平均等级 (A=95, B=80, C=60, D=0)
      - d_grade_count: D级（拒收）次数
      - total_inspections: 总质检次数

    算法:
      base = 100
      base -= rejection_rate * 100          # 每次拒收扣分
      base -= d_grade_count * 15            # 每次D级扣15分
      base += avg_grade_avg * 0.3           # 平均等级加分

    输出: 0 ~ 100 (clamp)
    """
```

**业务规则 (BR-01)**: 连续3次出现D级质检结果，质量分直接降至60分以下，触发"观察期"预警。

#### 3.2.2 交付分 (delivery_score, 权重 25%)

```python
def calc_delivery_score(order_data):
    """
    基于S03采购订单数据计算交付分

    输入:
      - on_time_rate: 准时率 (0~1)
      - avg_lead_time: 平均交货周期(小时)
      - partial_delivery_rate: 部分交货率

    算法:
      base = on_time_rate * 80               # 准时率占80分
      base += max(0, 20 - avg_lead_time / 24) # 交货周期越短越好(最多20分)
      base -= partial_delivery_rate * 10      # 部分交货扣分

    输出: 0 ~ 100
    """
```

**业务规则 (BR-02)**: 准时率低于70%时，交付分不超过50分。

#### 3.2.3 价格分 (price_score, 权重 20%)

```python
def calc_price_score(price_data):
    """
    基于S03订单单价 vs S01标准价计算价格分

    输入:
      - avg_price_vs_standard: 平均价格偏离度 (%)
      - price_stability: 价格稳定性 (变异系数)

    算法:
      base = 100
      if avg_price_vs_standard <= 0:  # 低于标准价
          base = min(100, 100 + abs(avg_price_vs_standard))  # 加分上限105
      else:
          base -= avg_price_vs_standard * 2  # 高于标准价扣分
      base -= price_stability * 10  # 价格波动扣分

    输出: 0 ~ 105 (可略超100表示价格优势)
    """
```

**业务规则 (BR-03)**: MVP阶段若无法获取市场比价数据，默认价格分=80（中性分），后续接入N02供应商比价后启用真实计算。

#### 3.2.4 服务分 (service_score, 权重 15%)

```python
def calc_service_score(service_data):
    """
    基于协同数据和人工评价计算服务分

    输入:
      - response_speed: 响应速度评分 (1-5)
      - return_cooperation: 退换货配合度 (1-5)
      - complaint_count: 客诉次数

    算法:
      base = response_speed * 16           # 响应速度 (最高80)
      base += return_cooperation * 4       # 配合度 (最高20)
      base -= complaint_count * 5          # 每次客诉扣5分

    输出: 0 ~ 100
    """
```

**业务规则 (BR-04)**: MVP阶段服务分默认75分（无足够数据时），仅支持人工调整。

### 3.3 综合评分与等级映射

```python
overall = (
    quality_score * 0.40 +
    delivery_score * 0.25 +
    price_score  * 0.20 +
    service_score * 0.15 +
    adjustment          # 人工调整
)

# 等级映射
if overall >= 90: grade = "A"  # 优秀 — 优先采购
elif overall >= 75: grade = "B"  # 良好 — 正常合作
elif overall >= 60: grade = "C"  # 及格 — 观察期
else: grade = "D"  # 不合格 — 考虑淘汰
```

### 3.4 评分触发时机

| 触发事件 | 动作 | 说明 |
|---------|------|------|
| S02 收货审批通过/拒收 | 重算质量分 | 单次质检影响该供应商质量维度 |
| S03 订单标记为 received | 重算交付分 | 到货确认后更新交付统计 |
| 月初 (1号) | 生成月度评分快照 | 形成历史趋势 |
| 人工调整 | 立即生效 | 特殊情况（如不可抗力）加减分 |

## 4. 供应商状态机

### 4.1 状态定义

```
                    ┌──────────┐
                    │  pending  │ ← 新建待审核
                    │ (待准入)  │
                    └────┬─────┘
                         │ 审核通过
                         ▼
                    ┌──────────┐
              ┌─────│  active   │────────┐
              │     │ (正常合作) │        │
              │     └────┬─────┘        │
              │          │              │
              │ 评分<C   │ 主动暂停      │ 评分连续改善
              │ 或违规   │              │
              │          ▼              │
              │    ┌──────────┐         │
              │    │ probation │─────────┘
              │    │ (观察期)  │  改善后恢复
              │    └────┬─────┘
              │         │ 再次违规
              │         ▼
              │    ┌───────────┐
              └────│ suspended  │────────┐
                   │ (已停用)   │        │
                   └─────┬─────┘        │
                         │ 严重违规     │ 期满/申诉成功
                         ▼              │
                   ┌───────────┐────────┘
                   │blacklisted │
                   │ (已拉黑)   │
                   └───────────┘
```

### 4.2 状态转换规则

| 当前状态 | 目标状态 | 触发条件 | 操作人 | BR编号 |
|---------|---------|---------|--------|--------|
| pending | active | 资质审核通过 | 潘厨 | BR-05 |
| pending | rejected | 资质不全/不符合要求 | 潘厨 | BR-06 |
| active | probation | 评分降至C级或收到重大投诉 | 系统/潘厨 | BR-07 |
| active | suspended | 主动暂停合作 | 潘厨 | BR-08 |
| probation | active | 连续2个月评分恢复至B级以上 | 系统 | BR-09 |
| probation | suspended | 观察期内再次违规 | 潘厨 | BR-10 |
| suspended | active | 期满重新激活 | 潘厨 | BR-11 |
| suspended | blacklisted | 严重违规（如食品安全问题） | 潘厨 | BR-12 |
| blacklisted | active | 申诉成功 + 重新审核 | 潘厨 | BR-13 |

**业务规则 (BR-14)**: 黑名单供应商不允许创建新的采购订单（S03层校验）。

## 7. 业务规则汇总 (BR-01 ~ BR-14)

| 编号 | 规则 | 严重级别 | 校验位置 |
|------|------|---------|---------|
| BR-01 | 连续3次D级质检 → 质量分<60 → 自动进入观察期 | P0 | Manager.calc_score() |
| BR-02 | 准时率<70% → 交付分≤50 | P0 | Manager.calc_delivery_score() |
| BR-03 | MVP阶段价格分默认80（无市场比价数据时） | P1 | Manager.calc_price_score() |
| BR-04 | MVP阶段服务分默认75（无足够评价数据时） | P1 | Manager.calc_service_score() |
| BR-05 | 新建供应商初始状态=pending，需审核激活 | P0 | Manager.create_supplier() |
| BR-06 | 资质不全可拒绝（pending→rejected，实际删除） | P0 | API层 |
| BR-07 | 评分降至C级 → 自动/建议转入观察期 | P0 | Manager.recalc_score() |
| BR-08 | 支持主动暂停合作（active→suspended） | P1 | Manager.suspend_supplier() |
| BR-09 | 观察期内连续2月评分恢复B级 → 自动恢复active | P0 | Manager.recalc_score() |
| BR-10 | 观察期内再违规 → 直接停用 | P0 | Manager.recalc_score() |
| BR-11 | 停用供应商可期满重新激活 | P1 | Manager.restore_supplier() |
| BR-12 | 严重违规（食品安全）可直接拉黑 | P0 | Manager.blacklist_supplier() |
| BR-13 | 黑名单供应商可申诉恢复（需重新全流程审核） | P2 | Manager.restore_supplier() |
| BR-14 | 黑名单供应商不允许创建新PO（S03层校验） | P0 | S03 Manager.create_purchase_order() |

## 10. 与其他模块联动

### 10.1 S02 → S04 联动（质检→评分）

```
S02 ReceivingRecord.approved()
  → 触发 SupplyChainManager.recalc_supplier_score(supplier_name)
  → 读取该供应商所有质检数据
  → 重算四维分 + 等级
  → 若降级 → 写入评分快照 + 状态变更检查
  → 若触发BR-01/BR-07/BR-10 → 自动状态转换
```

### 10.2 S03 → S04 联动（订单→评分）

```
S03 PurchaseOrder.mark_received()
  → 触发 SupplyChainManager.update_supplier_delivery_stats(supplier)
  → 更新准时率、订单数等统计
  → 重算交付分
```

### 10.3 S04 → S03 联动（状态→下单限制）

```
S03 PurchaseOrder.create_purchase_order()
  → 检查 supplier.status
  → 若 status in ['blacklisted', 'suspended']
  → 抛出 BusinessError("该供应商不可用")
```
