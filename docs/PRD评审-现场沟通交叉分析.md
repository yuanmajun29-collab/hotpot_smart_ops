## 1. 会议纪要核心要点提炼

> 来源：2026年7月27日火锅餐饮AI落地流程沟通会（已通过v5.3a嵌入PRD）

### 1.1 组织与对接关系

| # | 要点 | 核心含义 |
|---|------|----------|
| P1 | **潘总（潘厨）是品质核心对接人** | 所有品质标准、供应商管理最终由潘厨拍板 |
| P2 | **供应商王总方只对接潘厨** | 供应商协同端必须支持"单点对接"模式，不允许多头沟通 |
| P3 | **曹总统一下单标准** | 老板角色在供应链中起"标准定调"作用，系统需支持审批流 |

### 1.2 后厨核心管控：冻品供应链

| # | 要点 | 核心含义 |
|---|------|----------|
| P4 | **冻品供应链是后厨核心管控** | 冻品（牛羊肉卷、丸滑、海鲜等）占火锅食材成本大头，管控不力=利润流失 |
| P5 | **品牌/规格/品质一致性** | 同一品类必须锁定供应商+品牌+规格，防止供应商私下换货 |
| P6 | **货不对板/以次充好是最大痛点** | 如：订A级肥牛收到B级碎肉——缺乏系统化验收手段 |
| P7 | **供货名称/规格/品牌需固定** | 需要建立货品主数据标准库，供应商不可随意变更 |
| P8 | **变更提前反馈，不合格品退换货** | 规格变更有审批流，品质不达标自动触发退换货流程 |

### 1.3 前厅AI需求

| # | 要点 | 核心含义 |
|---|------|----------|
| P9 | **主动服务：感知客人需求与桌态** | AI需识别"客人四处张望/空杯/等人"等信号，主动推送服务提醒 |
| P10 | **人员行为与耗材管控** | 员工着装合规、服务响应时效、纸巾/湿巾/打包盒等耗材异常消耗监控 |

### 1.4 岗位AI助理

| # | 要点 | 核心含义 |
|---|------|----------|
| P11 | **每岗位配AI助理** | 店长、后厨、采购各有一个专属AI工作台 |
| P12 | **信息按角色聚合，不碎片化** | 每个角色只看到与自己相关的内容，不做"大而全"的通用面板 |

### 1.5 门店拓展与展会节奏

| # | 要点 | 核心含义 |
|---|------|----------|
| P13 | **先标准化现有2家→再拓新店** | 椒江→玉环→浙江新店，不能跳过标准化直接扩张 |
| P14 | **10月重庆市政府展会亮相** | 硬截止日，Demo必须展示冻品供应链+岗位助理的核心价值 |

### 1.6 收货/存货/出库流程

| # | 要点 | 核心含义 |
|---|------|----------|
| P15 | **收货/存货/出库流程需规范化** | 从供应商到货→扫码验收→入库→出库→加工出品，全链路标准化 |
| P16 | **库房空间有限，冻品拆放后盘点难** | 整箱冻品拆开放入不同冰柜/库位后，无法快速定位和盘点 |
| P17 | **不合格品退换货** | 流程需闭环：检测→判定→发起退换货→供应商确认→退货→补发 |

## 2. 逐条映射：现场需求→PRD功能→匹配度评分

> 评分标准：
> - ✅✅✅ **完全覆盖**：PRD有明确定义且EARS完整+验收标准清晰+有Sprint排期
> - ✅✅ **基本覆盖**：PRD有定义但EARS不够细、或验收标准待补全、或排期靠后
> - ✅ **部分覆盖**：PRD有提及但缺乏独立功能项、或与会议意图有偏差

## 3. 优先级校准评估

### 3.1 会议反复强调 vs PRD优先级分配

| 会议强调的主题 | 会议上强调频次 | PRD优先级 | 校准判断 |
|---------------|:--:|:--------:|------|
| 冻品供应链（品牌锁定+收货验收+退换货） | 🔴🔴🔴 最高频 | P0 (D1) | ✅ 一致 |
| 岗位AI助理（店长/后厨/采购） | 🔴🔴🔴 最高频 | P0 (D2) | ✅ 一致 |
| 流程标准化（收货→入库→出库） | 🔴🔴 高频 | P0(S01-S03)+P1(N21)+P1(K36) | 🟡 部分滞后 |
| 前厅主动服务 | 🔴🔴 高频 | P1(K33) | 🔴 **偏差** |
| 人员行为与耗材管控 | 🔴🔴 高频 | P1(K25/K26/K34) | 🟡 展会后 |
| 库房拆放盘点 | 🔴🔴 高频 | P1(N21)+P1(K36) | 🟡 展会后 |
| 供应商协同群 | 🔴 中频 | P1(N20) | 🟡 展会后 |
| 品质核心对接人（潘厨） | 🔴 中频 | A05(P1)+A04(P2) | ✅ 人工流程暂时兜底 |

### 3.2 优先级偏差分析

#### 偏差1：前厅主动服务(K33)应为P0而非P1

**会议证据**：潘总明确提出前厅AI需要"主动服务：感知客人需求与桌态"——这不是nice-to-have而是核心差异化。

**PRD现状**：K33主动服务提醒为P1（展会后开发），展会Demo只能展示K04/K05（基础桌态检测+空桌提醒）。

**影响**：
- 基础桌态（"桌子空了吗？"）vs 主动服务（"客人需要帮助吗？"）之间存在质的差距
- 竞品定位中（PRD §1.4），火瞳的核心差异化是"告诉你有问题+还告诉你怎么办"，但前厅AI如果只做桌态不做主动服务，在展会上与百度一见（视觉巡检）的差异化不够明显

**建议**：
- D2同时开发K33的MVP版本（仅覆盖"四处张望/空杯"两个最高频信号，不做全场景）
- 或至少在展会Demo中以"概念演示+真实数据回放"展示主动服务能力

#### 偏差2：库房拆放盘点(N21+K36)为展会后

**会议证据**："库房空间有限，冻品拆放后盘点难"——这是潘厨明确提出的运营痛点。

**PRD现状**：N21库位管理+K36库位定点标识均为P1（展会后）。

**影响**：展会Demo中"冻品供应链"故事讲到收货验收就结束了，缺少入库→库位→盘点→出库的后半段。而半段故事的说服力远低于全段故事——投资人会问："收了货之后呢？你们怎么管库存？"

**建议**：
- D1在S01货品主数据中附带简单的库位字段（名称+编码+存放区域），不追求完整N21
- 展会Demo设计为"收货验收→扫码入简单库位→出库提醒"的轻量故事线

## 4. 落地可行性审查

### 4.1 现实约束 vs PRD技术方案

| 现实约束 | PRD方案 | 可行性 | 风险 |
|----------|---------|:------:|------|
| 库房空间有限，拆放盘点难 | N21库位管理+K36库位定点标识 | 🟡 P1才实现 | D1阶段两店仍靠人工盘点，展会前无解决方案 |
| 冻品拆包后不可追溯 | S04冻品温控追溯 | 🟡 P2 | 不解决当前痛点，展会可讲概念但无实测数据 |
| 供货名称/规格不统一 | S01货品主数据管理 | 🟢 D1实现 | 依赖潘厨梳理完整货品清单，数据录入工作量是隐性成本 |
| 门店流程不统一 | 两店验证→标准化→复制 | 🟢 路线合理 | 但两店之间的差异有多大是未知数——如果椒江和玉环流程差异大，标准化时间可能超出D1-D2窗口 |
| 10月展会硬截止 | D1-D4仅~60个工作日 | 🔴 时间极度紧张 | 6个0%模块(S01-S03/A01-A03)需从零开发并集成测试 |
| 供应商数字化意愿 | 供应商协同端(A04)+协同群(N20) | 🟡 依赖王总方配合 | 供应商王总方如果不用智能手机或企微，S02/S03的"扫码验收+群通知"就落地不了 |
| 微信小程序开发 | A01-A03需微信+H5双端 | 🟡 前端未启动 | D2面临前后端并行开发，移动端是首次进入火瞳产品线 |

### 4.2 可行性关键假设检验

| 假设 | 证据强度 | 风险等级 |
|------|:--:|:--:|
| "王总方会用企微扫码" | 未验证 | 🔴 高——如果王总方是传统冻品批发商，数字化能力可能是0 |
| "潘厨能在一周内梳理完货品主数据" | 潘厨是品质负责人，有经验 | 🟡 中——完整梳理可能有几十个SKU |
| "两店流程差异可在D1前对齐" | 未验证 | 🟡 中——流程差异调研尚未进行 |
| "微信小程序+H5可在4周内完成三角色助理" | 火瞳团队首次做移动端 | 🔴 高——建议先用微信模板消息+简单H5 MVP |
| "冻品收货验收的视觉AI（品牌规格比对）准确率>98%" | K12以劣充好检测已有代码基础 | 🟡 中——冻品包装识别是新的视觉任务，需额外训练数据 |

### 4.3 落地保底方案建议

| 场景 | Plan A（PRD设计） | Plan B（保底方案） |
