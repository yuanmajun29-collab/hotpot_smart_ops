## 六、IP-5 Gateway合规流程详解

### 6.1 为什么需要Gateway？

**行业背景**:
- 国家《生成式AI服务管理办法》要求：AI不得自主做出重大商业决策
- 餐饮行业规范：采购订单必须有审批流程
- 商家诉求：每一笔支出都要可控、可追溯

**技术挑战**:
- 传统做法：硬编码if-else判断 → 难以维护、容易遗漏
- 火瞳方案：统一Gateway中间件 → 声明式配置、自动路由

### 6.2 Gateway架构图

```
┌─────────────────────────────────────────────────────┐
│                  岗位AI助理 (D2)                      │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐   │
│  │店长助理  │ │后厨助理  │ │采购助理  │ │供应商门户│   │
│  └────┬────┘ └────┬────┘ └────┬────┘ └────┬────┘   │
```

## 七、故障处理FAQ

### 7.1 常见问题速查表

| 问题 | 可能原因 | 解决方案 | 耗时 |
|------|---------|---------|:----:|
| **无法访问172.16.1.60:9080** | Jetson未启动/网络不通 | 检查电源+网线指示灯 | 1分钟 |
| **登录页面打不开** | Edge UI进程崩溃 | 重启服务（见8.1节） | 2分钟 |
| **PIN码错误** | 输入错误/大小写 | 确认123456，无大小写 | 10秒 |
| **页面显示空白** | 浏览器兼容性 | 换Chrome/Firefox | 30秒 |
| **API返回500错误** | 后端异常 | 查看日志 `/tmp/edge-ui-final.log` | 2分钟 |
| **Demo数据为空** | 未初始化 | 执行 `demo_runner.py --mode init` | 1分钟 |
| **IP-5流程卡住** | 待审批任务未生成 | 检查Gateway是否启用 | 1分钟 |
| **响应很慢** | Jetson负载高 | 减少并发，清理缓存 | 2分钟 |

### 7.2 详细故障排查

#### Q1: Edge UI无法启动

```bash
# Step 1: 检查进程是否存在
ps aux | grep main.py | grep -v grep

# Step 2: 如果不存在，手动启动
cd /opt/hotpot-smart-ops/edge/edge-ui
PYTHONPATH=/opt/hotpot-smart-ops nohup python3 main.py --port 9080 > /tmp/edge-ui-restart.log 2>&1 &

# Step 3: 等待3秒后验证
sleep 3 && curl -s http://127.0.0.1:9080/api/v1/auth/ping
```

#### Q2: Gateway端点返回404

```bash
# 检查Gateway是否正确加载
curl -s http://127.0.0.1:9080/openapi.json | python3 -c \
  "import sys,json; d=json.load(sys.stdin); print([p for p in d['paths'] if 'gateway' in p])"

# 如果返回空列表，说明导入失败，需要：
# 1. 清除缓存: find /opt/hotpot-smart-ops -name __pycache__ -exec rm -rf {} +
# 2. 重启服务: 见Q1
```

#### Q3: Demo数据丢失

```bash
# 重新初始化Demo数据
cd /opt/hotpot-smart-ops
PYTHONPATH=/opt/hotpot-smart-ops python3 demo/demo_runner.py --mode init --force

# 验证数据
curl -s http://127.0.0.1:9080/api/v1/supply-chain/products | python3 -c \
  "import sys,json; d=json.load(sys.stdin); print(f'Products: {len(d.get(\"data\",[]))}')"
```

## 八、应急方案

### 8.1 离线演示模式（断网备用）

**触发条件**: 展会现场无法连接Jetson（网络故障/IP冲突）

**备用方案**:
1. **预录制视频**（推荐提前准备）
   - 录制完整的15分钟演示视频（含旁白）
   - 存储在本地笔记本/U盘
   - 使用VLC/OBS播放，可暂停讲解

2. **截图PPT备份**
   - 每个场景的关键截图（20-30张）
   - 制作成PPT，按演示顺序排列
   - 配合口头讲解

3. **本地Mock服务器**
   ```bash
   # 在笔记本上启动Mock服务（无需Jetson）
   cd hotpot_smart_ops/demo
   python3 -m http.server 8080 --directory mock_data/
   # 浏览器访问 localhost:8080
   ```

### 8.2 设备故障备用

| 故障设备 | 备用方案 | 切换时间 |
|---------|---------|:--------:|
| Jetson主机损坏 | 备用笔记本跑Mock服务 | 5分钟 |
| 显示器损坏 | 使用投影仪/备用显示器 | 2分钟 |
| 网线损坏 | WiFi连接（如有）或手机热点 | 3分钟 |
| 键盘鼠标损坏 | 使用触摸屏/外接蓝牙 | 1分钟 |

### 8.3 演示中断恢复

**如果在演示过程中出现故障**:

1. **保持冷静**（最重要！）
2. **幽默化解**: "看来AI也想休息一下 😄"
3. **切换备用方案**: 立即切换到离线模式
4. **继续演示**: 不要纠结于故障，继续下一个场景
5. **事后复盘**: 记录故障原因，避免下次发生
