## 2. 目录角色

| 目录 | 角色 | 准入 |
|------|------|------|
| `01-核心权威/` | 现行权威 + 整改输入 | 仅活跃基线；历史正文不进此目录 |
| `02-市场调研/` | 调研报告 | 可标注「相对 PRD 过期」 |
| `02-实施方案/` | 门店实例 / 部署验收基线 | 实例配置，不替代 PRD |
| `03-产品设计/` | 现行产品设计 + 思想源 | 历史产品文进 `archive/` |
| `04-技术设计/` | ADR / 模块详设 / 数据标准 | ADR 编号唯一；过期基线标历史 |
| `05-功能规格/` | Spec / 测试用例 | 按功能 ID |
| `06-调研照片/` | 实地照片 | — |
| `07-业务参考/` | 展会 / 定价 / 采集表 | 业务侧参考 |
| `08-评审/` | 评审 / DoR / Backlog | 过程资产，非需求权威 |
| `08-运维/` | 运维手册 | — |
| `archive/` | 归档（完成报告、重复副本、被取代设计） | **只读**；禁止再被引用为「当前权威」 |

根目录 `docs/*.md` **禁止再新增** Sprint 完成报告或权威文档副本；新报告一律进 `08-评审/` 或 `archive/sprint-reports/`。

## 3. 编号规则（与 PRD §1 一致）

| 前缀 | 含义 | 示例 |
|------|------|------|
| **BD1–BD5** | 业务域 | BD1 后厨、BD2 供应链 |
| **S1–S4** | 展会冲刺 Sprint | 原 D1–D4 冲刺 |
| **D1–D4** | 仅数据验证等级 | 设计→代码→模拟→真实门店 |
| **K/N/S/A/H/…** | PRD 功能 ID | 以 PRD §3 为唯一源 |
| **G-BD*** | 缺口追踪 | G-BD2-1 |

禁止再用「D1」同时指业务域与冲刺。旧文出现时视为历史措辞，以本表为准。

## 4. 成熟度口径

| 级别 | 含义 | 不算证据 |
|------|------|----------|
| 📋 L1 | 需求/设计已定义 | — |
| 🔧 L2 | 可运行代码 / Demo | — |
| ✅ L3 | 真实门店 ≥7 天 + KPI 回写 | 回测、Demo、部署报告 |
| ⭐ L4 | 多店复用 + ROI | — |

对外材料不得把 MAPE 回测单独写成「已验证通过 / L3」。

## 5. 历史 / 归档处理规则

1. **被取代文档**：移入 `archive/`，原路径可留 5～10 行跳转 stub（可选）。
2. **重复副本**：根目录与分类目录 MD5 相同或同源 → 只保留分类目录一份，根副本归档。
3. **Sprint 完成报告**：一律 `archive/sprint-reports/`，不进 `01-核心权威/`。
4. **引用写法**：活跃文档写「当前权威 = PRD **v5.3q**」；禁止写「当前权威 = v5.3o/p/n」等过期指针。
5. **代码对齐表**：`04-技术设计/PRD_V5_3i_CODE_ALIGNMENT.md` 降为**历史快照**；现行成熟度以 PRD §1.9 + `目标vs实现状态对照表` 为准。
