## 一、集成背景与目标

### 1.1 当前状态

```
✅ D1 冻品供应链 (4模块)
   ├─ S01 货品主数据 → 数据已就绪
   ├─ S02 收货质检 → 数据已就绪
   ├─ S03 采购订单 → 数据已就绪
   └─ S04 供应商协同 → 数据已就绪

✅ D2 岗位AI助理 (4角色)
   ├─ A01 店长数字座舱 → API+前端完整
   ├─ A02 厨师长工作台 → API+前端完整
   ├─ A03 采购工作台 → API+前端完整
   └─ A04 供应商门户 → API+前端完整

⏳ D3 集成测试 (待开发)
   └─ 目标: 打通D1↔D2数据流，实现端到端闭环
```

### 1.2 集成目标

| # | 目标 | 描述 | 验收标准 |
|---|------|------|----------|
| G1 | **数据流打通** | D1产生的数据能自动流入D2的AI建议引擎 | Dashboard显示真实KPI而非Mock |
| G2 | **决策闭环** | D2的AI建议能触发D1的操作（如创建采购订单） | 采纳建议→自动生成PO |
| G3 | **事件联动** | D1的事件（如收货异常）能触发D2的任务推送 | 收货不合格→店长任务列表出现提醒 |
| G4 | **性能达标** | 端到端延迟≤2秒（边缘盒子本地） | 压测通过 |

### 1.3 非目标（明确排除）

- ❌ 不涉及视觉AI引擎（摄像头）的集成（独立模块）
- ❌ 不涉及云端平台的数据同步（D4阶段）
- ❌ 不涉及多门店数据聚合（后续版本）

### 2.2 核心集成点清单

#### IP-1: 货品主数据 → 采购建议

| 维度 | 说明 |
|------|------|
| **数据源** | `SupplyChainManager.get_products()` → ProductMaster列表 |
| **消费者** | `AssistantEngine.generate_purchase_suggestions()` |
| **数据内容** | 商品名称/分类/单位/安全库存/最近7天销量/均价 |
| **集成方式** | D2 Manager直接调用D1 Manager方法（同进程） |
| **优先级** | **P0** (核心功能) |
| **复杂度** | 中（需处理数据格式转换） |

#### IP-2: 收货质检 → 损耗预警 + 任务推送

| 维度 | 说明 |
|------|------|
| **数据源** | `ReceivingQualityManager` 的质检记录 |
| **消费者** | Dashboard任务列表 + Kitchen损耗监控 |
| **数据内容** | 质检结果(合格/不合格)/问题类型/涉及商品/金额 |
| **集成方式** | 事件驱动：质检完成后发布事件 → D2监听并生成任务 |
| **优先级** | **P0** (核心闭环) |
| **复杂度** | 高（需要事件总线机制） |

#### IP-3: 采购订单 → 订单跟踪 + 供应商比价

| 维度 | 说明 |
|------|------|
| **数据源** | `PurchaseOrderManager` 的订单状态机 |
| **消费者** | Purchase面板的订单跟踪列表 + 供应商比价表 |
| **数据内容** | PO编号/供应商/金额/状态(待确认→已确认→部分收货→已完成) |
| **集成方式** | 定时轮询或WebSocket推送 |
| **优先级** | **P1** (增强体验) |
| **复杂度** | 中（状态同步逻辑） |

#### IP-4: 供应商评分 → 供应商门户 + 比价参考

| 维度 | 说明 |
|------|------|
| **数据源** | `SupplierScoreEngine` 的评分结果 |
| **消费者** | Supplier Portal的KPI + Purchase比价表的评级列 |
| **数据内容** | 综合分(A/B/C/D)/品质分/准时率/交期/合作时长 |
| **集成方式** | 直接查询（低频更新，缓存即可） |
| **优先级** | **P1** (增强体验) |
| **复杂度** | 低（只读数据） |

#### IP-5: AI建议采纳 → 自动创建采购订单

| 维度 | 说明 |
|------|------|
| **触发器** | 用户点击"采纳"采购建议按钮 |
| **执行动作** | 调用 `PurchaseOrderManager.create_order()` |
| **反馈** | 返回新PO编号，刷新订单跟踪列表 |
| **优先级** | **P0** (核心闭环) |
| **复杂度** | 高（跨模块事务一致性） |

## 三、集成架构设计

### 3.1 推荐架构: 同进程直接调用

```python
# edge/edge-ui/api/assistant_api.py (扩展现有代码)

from hotpot_platform.cloud.supply_chain.manager import SupplyChainManager
from hotpot_platform.cloud.supply_chain.models import PurchaseOrder, ReceivingRecord

# 初始化D1 Manager（单例）
sc_manager = SupplyChainManager()

@router.get("/dashboard")
async def get_dashboard(store_id: str = "jiaojiang"):
    # 从D1获取真实数据
    products = sc_manager.get_products(store_id=store_id)
    recent_orders = sc_manager.get_recent_orders(store_id=store_id, days=7)
    quality_issues = sc_manager.get_quality_issues(store_id=store_id, days=3)
    
    # 注入到AI引擎
    dashboard_data = assistant_engine.build_dashboard(
        products=products,
        orders=recent_orders,
        quality_records=quality_issues,
        store_id=store_id
    )
    
    return {"code": 0, "data": dashboard_data}
```

**优点**: 
- ✅ 实现简单（同进程无网络开销）
- ✅ 事务一致性好（共享数据库连接）
- ✅ 延迟低（毫秒级）

**缺点**:
- ⚠️ 耦合度高（D1和D2代码强依赖）
- ⚠️ 测试需要同时启动两个模块

### 3.2 备选架构: 事件总线解耦

```python
# 使用简单的事件发布-订阅模式

class EventBus:
    def __init__(self):
        self.subscribers = {}
    
    def subscribe(self, event_type, handler):
        if event_type not in self.subscribers:
            self.subscribers[event_type] = []
        self.subscribers[event_type].append(handler)
    
    def publish(self, event_type, data):
        for handler in self.subscribers.get(event_type, []):
            handler(data)

# 全局事件总线实例
event_bus = EventBus()

# D2订阅D1的事件
event_bus.subscribe("quality_check_completed", on_quality_event)
event_bus.subscribe("order_status_changed", on_order_event)

# D1发布事件
event_bus.publish("quality_check_completed", {
    "record_id": "R-20260801-003",
    "result": "FAIL",
    "product": "牛肉",
    "issue": "解冻过度",
    "amount": 256.0
})
```

**适用场景**: IP-2（质检→任务推送）、IP-3（订单状态变更）
