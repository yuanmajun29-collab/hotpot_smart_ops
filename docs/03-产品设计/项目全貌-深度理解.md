## 1. 产品灵魂

### 一句话定位

> **火瞳——冯校长火锅连锁AI运营中台。摄像头看见后厨，AI算清订货，手机上管所有店。**
>
> — PRD **v5.3i** §1.1 L45-49

**完整版**：「摄像头替你看后厨，AI 替你算订货，手机上管所有店。」（PRD L48）

五层能力栈：看得见的损失（视觉 AI 废料检测）+ 算得清的订货（AI 销量预测+库存优化）+ 管得住的连锁（多店总览+SOP 合规+供应商画像）+ 管得了的冻品（品牌规格锁定+温控追溯+退换货流程）+ 配得上的助理（每个岗位一个 AI 入口）。（PRD L49）

### 定位与边界

| 维度 | 内容 | 来源 |
|------|------|------|
| 品牌名 | 火瞳 🔥👁️ | 产品设计分析 §1 L32 |
| 内部定位 | 冯校长连锁运营中台 | PRD §1.1 L42 |
| 技术描述 | 视觉+数据双引擎AI运营系统 | PRD §1.1 L43 |
| 当前阶段 | 两店验证（椒江+玉环） | PRD §1.2 L55-57 |
| 硬截止日 | 2026年10月重庆市政府展会 | PRD §10.5 L653 |
| 开发分支 | `feature/arch-design`（架构设计） | CLAUDE.md L39 |

**明确边界**（PRD §1.3 L60-64）：
- 火瞳**连接** POS、ERP、库存、采购和会员系统，**不取代**它们
- 给出预警、损耗估算和订货建议；正式采购和库存扣减**必须由授权人员确认**
- 当前聚焦火锅业态；未来可扩展至「火锅+」多业态，但不在当前版本范围内

### 竞争哲学与定价哲学

**经营哲学核心**（`火锅AI-经营哲学.md` L22）：「拿得少，走得远。」拿得多的人，会被拿得少的人打败。

- BOM 成本 ¥6,990 可公开（经营哲学 L29）
- 十个月收回设备成本就够（经营哲学 L34）
- ¥7,800/年不是定价策略而是愿景（经营哲学 L27）
- 对外定价当前不执行——**先用自有门店跑出真实 ROI 数据（10 月展会）再定价**（PRD §9.2 L622）

### 三阶段路线（PRD §1.2 L52-57）

| 阶段 | 目标 | 门槛 | 当前状态 |
|------|------|------|:--:|
| **两店验证** | 椒江、玉环真实数据和流程跑通 | 原始POS + 人工核验 + 店长确认 | 🟡 进行中 |
| **区域标准化** | 形成浙江新店部署与运营标准 | 两店可复用 + 数据一致 + 部署可控 | ⏳ 待展会后 |
| **对外输出** | 向体系内及外部连锁复制 | 真实ROI + 稳定交付 + 合规定价 | ⏳ 待区域标准化后 |

### 定位演进（产品设计分析 §1 L57-63）

```
v5.0（早期）: 通用火锅后厨AI → 面向外部SaaS → 客群/定价/扩张口径偏快
    ↓ （WorkBuddy v5.2 自有品牌修订）
v5.2: 自有连锁优先 → 两店验证 → "先服务自己，再对外输出"
    ↓ （7/27会议 + 市场调研）
v5.3c: 冻品供应链 + 岗位AI助理 + 10月展会冲刺 → 63项功能EARS
    ↓ （v5.3d~v5.3i 多次扩展：场景工作流+全场景覆盖+连锁管控）
v5.3i: 129项功能EARS（当前基线）
```

**关键洞察**：定位从「卖出去」（SaaS）纠正为「先用好」（自有验证），是 PRD v5.2→v5.3 最关键的修正。v5.0 旧口径的「客户数」「定价」「扩张」等外部指标已被 v5.3 的三阶段路线和 Go/No-Go 门控替代。（产品设计分析 §1 L65）

### 2.3 核心设计模式（产品设计分析 §5.2 L283-292）

### 4.3 识别的主要偏差

**偏差1：前厅主动服务(K33)应为 P0 而非 P1**（交叉分析 §3.2 L167-179）

会议证据：潘总明确提出前厅 AI 需要「主动服务：感知客人需求与桌态」——这不是 nice-to-have 而是核心差异化。  
PRD 现状：K33 主动服务提醒为 P1（展会后开发），展会 Demo 只能展示 K04/K05（基础桌态检测+空桌提醒）。  
影响：基础桌态 vs 主动服务之间存在质的差距。火瞳核心差异化「告诉你有问题+还告诉你怎么办」在前厅 AI 上体现不足。  
**建议**：D2 同时开发 K33 的 MVP 版本（仅覆盖「四处张望/空杯」两个最高频信号），或至少在展会 Demo 中以「概念演示+真实数据回放」展示主动服务能力。

**偏差2：库房拆放盘点(N21+K36)为展会后，展会故事半段而止**（交叉分析 §3.2 L181-192）

会议证据：潘厨明确「库房空间有限，冻品拆放后盘点难」。  
影响：展会 Demo 中「冻品供应链」故事讲到收货验收就结束，缺少入库→库位→盘点→出库的后半段。投资人会问：「收了货之后呢？你们怎么管库存？」  
**建议**：D1 在 S01 中附带简单库位字段（名称+编码+存放区域），不追求完整 N21。展会 Demo 设计为「收货验收→扫码入简单库位→出库提醒」的轻量故事线。
