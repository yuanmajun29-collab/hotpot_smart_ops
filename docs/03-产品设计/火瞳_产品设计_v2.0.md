## 1. 产品定位与边界

### 1.1 一句话

> **摄像头看见后厨异常，数据引擎算清订货，手机上管所有店。**

### 1.2 产品定义

| 维度 | 内容 |
|------|------|
| **品牌名** | 火瞳 🔥👁️ |
| **内部定位** | 冯校长连锁运营中台 |
| **技术描述** | 视觉+数据双引擎 AI 运营系统 |
| **当前阶段** | 两店验证（椒江+玉环） |
| **硬截止日** | 2026年10月重庆市政府展会 |
| **竞争差异** | 百度一见做"看见"，火瞳做"看见+算清+管住"（双引擎闭环） |

### 1.3 明确边界

- ✅ 连接 POS、ERP、库存、采购和会员系统，**不取代**它们
- ✅ 给出预警、损耗估算和订货建议；正式采购和库存扣减**必须由授权人员确认**
- ✅ 当前优先两家自营店（椒江+玉环）
- ✅ 聚焦火锅业态；未来可扩展至"火锅+"多业态
- ❌ AI 不自动创建正式采购订单（PRD FS-01）
- ❌ 不对员工行为实施自动处罚（PRD FS-05）

### 1.4 三阶段路线

```
两店验证(当前) → 区域标准化(展会后) → 对外输出(2027)
  椒江+玉环        浙江新店部署标准    体系内外复制
  Go/No-Go         可复用·数据一致    真实ROI·稳定交付
```

## 3. BD1 后厨食安与损耗管控

### 3.1 业务痛点

- 食材损耗率 12-15%，看不见摸不着
- SOP 执行靠人盯，新员工培训周期长
- 出品率波动大（毛肚切片厚度、摆盘标准不一致）
- 食安风险（温度异常、临期食材）发现不及时

### 3.2 产品解决方案

| 功能ID | 功能名称 | 描述 | 成熟度 |
|:------:|----------|------|:------:|
| K01 | AI废料检测 | YOLO+CLIP+VLM三级过滤，检测后厨废料区 | 🔧 L2 |
| K02 | 废料分类统计 | 按食材/工位/时段/原因四维分类 | 🔧 L2 |
| K03 | 损耗成本核算 | 废料量→食材单价→损耗金额自动计算 | 🔧 L2 |
| K27 | SOP合规评分 | 7工位操作规范AI检测+加权评分 | 🔧 L2 |
| K31 | 出品质检 | CLIP模型对比出品标准，检测摆盘/份量 | 🔧 L2 |
| K35 | 出品率管控 | 食材投入→成品产出转化率统计 | 📋 L1 |
| K36 | 库位定点标识 | RFID/二维码定点管理食材库位 | 📋 L1 |
| I01-I03 | IoT废料闭环 | 称重+拍照+原因分类三件套 | 🔧 L2 |

### 3.3 关键指标

| KPI | 当前基线 | 展前目标 | 长期目标 |
|-----|:------:|:------:|:------:|
| 损耗率 | ~15% | ≤10% | ≤5% |
| SOP合规率 | 人工抽查~70% | AI覆盖7工位 | ≥90% |
| 出品率 | 未统计 | 基准建立 | ≥85% |
| 废料检测准确率 | 单摄像机~80% | 5路改造后≥85% | ≥90% |

## 4. BD2 供应链利润管理

### 4.1 业务痛点

- 订货凭经验，不凭数据（MAPE ~45%规则/20% SARIMA）
- 冻品货不对板、品牌规格被替换
- 供应商绩效无量化评估
- 库存积压与缺货并存

### 4.2 产品解决方案

| 功能ID | 功能名称 | 描述 | 成熟度 |
|:------:|----------|------|:------:|
| S01 | 货品主数据 | 锁定品牌/规格/价格/供应商四要素 | 🔧 L2 |
| S02 | AI收货质检 | VLM辅助：包装logo识别+规格比对+溯源凭证 | 🔧 L2 |
| S03 | 采购订单管理 | 含审批流：建议→确认→下单→到货→验收 | 🔧 L2 |
| S04 | 供应商协同 | 评分卡+协同群+退换货流程 | 🔧 L2 |
| N01 | AI销量预测 | 四级降级链：L1规则→L2 SARIMA→L3 LightGBM→L4 LLM | 🔧 L2 |
| N02 | 智能订货 | EOQ/报童/安全库存三种模型驱动订货建议 | 🔧 L2 |
| N03 | 库存监控 | 日快照+水位预警+FIFO临期提醒 | 🔧 L2 |
| N04 | 损耗闭环 | ✅ 唯一L3：椒江7天真实门店验证通过 | ✅ L3 |
| N07-N09 | 供应商画像/评级/对账 | 量化评估+自动对账 | 📋 L1 |
| N19-N21 | 跨店调拨/协同/库位 | Phase2多店功能 | 📋 L1 |

### 4.3 关键指标

| KPI | 当前基线 | 展前目标 | 长期目标 |

| 订货建议采纳率 | — | ≥60% | ≥80% |

## 8. 岗位 Agent 三段式工作流

> **设计原则**：每个岗位 Agent 覆盖班前（准备）、班中（执行）、班后（复盘）三个时段。
> 每个时段有明确的推送内容、需确认的任务、和超时升级规则。

### 8.1 A01 店长助理

#### 班前（开店前 30 分钟）

| 动作 | 内容 | 推送方式 |
|------|------|----------|
| 📊 昨日经营简报 | 昨日营收、损耗、翻台率、异常事件汇总 | Dashboard卡片 + 微信推送 |
| 📋 今日待办清单 | 系统自动生成：采购待审批/异常待处理/SOP提醒 | Edge UI 待办列表 |
| 🔔 预警汇总 | 库存不足预警、临期食材提醒、设备异常 | Dashboard 告警栏 |
| ✅ 确认动作 | 确认今日班次人员、确认采购审批项 | 一键确认按钮 |

#### 班中（运营时段）

| 动作 | 内容 | 推送方式 |
|------|------|----------|
| 🔴 实时异常 | 废料异常(Severity HIGH)、温度告警、SOP严重违规 | 即时推送+超时升级 |
| 📊 实时看板 | 当前翻台率、在店桌数、出品速度 | Dashboard 实时刷新 |
| 📝 任务跟进 | 已分配任务的完成状态 | 任务列表+进度条 |
| 🔄 跨岗协调 | 采购/后厨/前厅间的协作请求 | Agent消息总线 |

#### 班后（关店后 1 小时）

| 动作 | 内容 | 推送方式 |
|------|------|----------|
| 📊 今日经营报告 | 自动生成：营收、损耗、翻台、SOP评分、采购执行率 | Dashboard报告+微信推送 |
| 🔍 异常复盘 | 今日全部异常事件+处理结果+未闭环项 | 复盘列表 |
| 📝 明日准备 | 自动生成明日待办：采购建议、排班提醒、备货清单 | Edge UI |
| ✅ 确认动作 | 确认今日损耗明细、审批明日采购建议 | 手机确认 |

### 8.2 A02 后厨助理

| 时段 | 动作 | 对应功能 |
|------|------|----------|
| **班前** | ① 接收今日备货清单（N02驱动）② SOP今日重点提醒 ③ 查看昨日出品率/损耗复盘 | N02, K27 |
| **班中** | ① 实时废料推送（K01→手机）② 温度异常告警（K19）③ SOP操作指引（切配/摆盘标准）④ 临期食材提醒 | K01, K19, K27, N03 |
| **班后** | ① 确认当日废料明细+原因分类 ② 确认出品率统计 ③ 提交次日备货需求 | K01, K35, N02 |

### 8.3 A03 采购助理

| 时段 | 动作 | 对应功能 |
|------|------|----------|
| **班前** | ① 接收今日订货建议（N02）② 查看供应商到货计划 ③ 价格波动预警 | N02, S04 |
| **班中** | ① 处理采购审批（店长确认后执行）② 跟进到货验收（S02）③ 退换货流程跟进 | S03, S02 |
| **班后** | ① 确认当日采购执行率 ② 更新供应商交付记录 ③ 提交次日采购预测 | N01, S04 |

### 8.4 A04 供应商端

| 时段 | 动作 | 对应功能 |
|------|------|----------|
| **班前** | ① 接收今日订单通知 ② 确认配送计划 | S03 |
| **班中** | ① 配送状态上报 ② 质量问题响应 | S02, S04 |
| **班后** | ① 查看评分卡更新 ② 补货建议 | N05 |

### 8.5 A05 知识库助理

| 时段 | 动作 | 对应功能 |
|------|------|----------|
| **班前** | ① 推送今日SOP重点（新菜品/季节性变更）② 新员工培训任务推送 | A05 |
| **班中** | ① SOP查询（"毛肚切片标准厚度？"）② 话术查询（"推荐锅底怎么说？"） | A05 |
| **班后** | ① 更新知识库（今日新增问题及回答）② 培训完成度统计 | A05 |

## 9. 订阅与推送机制

### 9.1 设计原则

> **每个角色只接收与其职责相关的信息。信息分层不轰炸。**

### 9.2 推送渠道矩阵

| 渠道 | 适用场景 | 延迟 | 确认率 |
|------|----------|:----:|:------:|
| Edge UI Dashboard | 在线时实时看板 | 实时 | — |
| 微信模板消息 | 离线时重要通知 | <5秒 | ~70% |
| 短信 | 超时升级+紧急告警 | <10秒 | ~95% |
| 电话自动拨打 | 安全告警（火灾等） | <30秒 | ~99% |

### 9.3 角色默认订阅

| 角色 | 订阅事件 | 推送频率 | 静默时段 |
|------|----------|----------|----------|
| 店长 (A01) | 废料HIGH+采购建议+SOP违规+经营日报 | 实时+日汇总 | 22:00-06:00 |
| 后厨 (A02) | 废料全部+温度异常+SOP提醒 | 实时+班次汇总 | 关店后 |
| 采购 (A03) | 库存预警+供应商反馈+价格波动 | 实时 | 22:00-06:00 |
| 供应商 (A04) | 订单通知+品质反馈+评分更新 | 工作日 | — |

### 9.4 超时升级链路

```
L1直接责任人 → (N分钟未处理) → L2领班/组长 → (M分钟) → L3店长
```

| 事件类型 | L1→L2 | L2→L3 | 最终动作 |
|----------|:-----:|:-----:|----------|
| 废料事件 | 3min | 5min | 店长强提醒 |
| 温度异常 | 2min | 5min | 自动拨打电话 |
| SOP违规 | 5min | 15min | 记入日报 |
| 采购建议 | 30min | 2h | 标记过期 |
| 安全告警 | 立即 | 1min | 全店广播 |

## 10. 样板店策略

### 10.1 定位

| 属性 | 椒江样板店 | 通用平台目标 |

## 11. 销售培训设计

### 11.1 培训体系

| 层级 | 对象 | 内容 | 工具 |
|------|------|------|------|
| L1 入职培训 | 新员工 | 火锅基础、SOP操作、安全规范 | A05知识库+视频 |
| L2 岗位培训 | 在岗员工 | 切配标准、摆盘规范、服务话术 | A05实时查询+SOP评分反馈 |
| L3 晋升培训 | 领班/主管 | 排班管理、损耗管控、顾客投诉处理 | A01店长助理+数据分析 |

### 11.2 AI辅助培训

- **SOP实时指导**：后厨操作时，A02推送标准操作步骤（如"毛肚切片厚度2mm，摆盘8片/份"）
- **服务话术推荐**：A05根据顾客画像推荐话术（新客→招牌推荐，老客→偏好推荐）
- **培训效果追踪**：SOP合规评分作为培训效果量化指标

### 11.3 展会培训演示要点

- 演示A05的SOP查询功能：输入"毛肚怎么切"→标准回答
- 演示A02的实时SOP提醒：切配工位自动弹出操作标准
- 展示培训效果：SOP评分从入职时的60分→1周后的85分

## 12. KPI 体系

### 12.1 一级指标（经营层）

| KPI | 定义 | 数据来源 | 目标 |
|-----|------|----------|:----:|
| 单店月利润 | 营收 - 食材成本 - 人工 - 运营费用 | POS + ERP | ↑15% |
| ROI | (利润 - 火瞳成本) / 火瞳成本 | 财务系统 | ≥5x |
| 损耗率 | 废料成本 / 食材总成本 | K01+K03 | ≤5% |
| 翻台率 | 日均翻台次数 | K04+K13 | ≥2.5 |

### 12.2 二级指标（运营层）

| KPI | 定义 | 数据来源 | 目标 |
|-----|------|----------|:----:|
| SOP合规率 | AI评分达标次数/总检测次数 | K27 | ≥90% |
| 预测MAPE | |预测值-实际值|/实际值 均值 | N01 | ≤15% |
| 订货建议采纳率 | 采纳次数/建议次数 | N02 | ≥80% |
| 出品率 | 成品重量/食材投入重量 | K35 | ≥85% |
| 供应商评分 | 综合质量/交付/价格评分 | N05 | ≥80分 |

### 12.3 三级指标（执行层）

| KPI | 定义 | 数据来源 |
|-----|------|----------|
| 废料确认及时率 | 规定时间内确认的废料事件占比 | K01 |
| 温度异常响应时间 | 告警→处理的平均时间 | K19 |
| 空桌清理时间 | 顾客离开→桌面清理完成时间 | K04+K05 |
| 采购审批周期 | 建议生成→店长审批完成时间 | S03 |
