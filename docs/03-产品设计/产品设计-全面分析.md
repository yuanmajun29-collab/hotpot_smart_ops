## 1. 产品定位

### 一句话

> **火瞳——冯校长火锅连锁AI运营中台。摄像头看见后厨异常，数据引擎算清订货，手机上管所有店。**
>
> （PRD **v5.3i** §1.1）

| 要素 | 内容 |
|------|------|
| **品牌名** | 火瞳 🔥👁️ |
| **内部定位** | 冯校长连锁运营中台 |
| **技术描述** | 视觉+数据双引擎AI运营系统 |
| **当前阶段** | 两店验证（椒江+玉环） |
| **硬截止日** | 2026年10月重庆市政府展会 |

### 解决的问题

| 问题 | 火瞳方案 | 证据 |
|------|----------|------|
| 后厨食材损耗12-15%，看不见摸不着 | YOLO视觉AI检测废料区，实时计数+推送到Dashboard | K01-K03 代码基础，CLAUD光检测流程已实现 |
| 订货凭经验，不是凭数据 | 四级预测引擎（L1规则→L2 SARIMA→L3 LightGBM→L4 LLM），提前1-7天预测每SKU需求量 | N01 SalesPredictor 352行代码，MAPE 10.6%（椒江店回测Go） |
| 多店管理靠巡店，人不够用 | 多店Dashboard+对比排名+区域总代看板，手机上管所有店 | K06-K08/K15/K23/K29 代码基础 |
| 冻品供应链货不对板、以次充好 | S01货品主数据锁定品牌规格 + S02收货扫码比对 + S03退换货自动流程 | 7/27会议驱动，D1冲刺中 |
| 各岗位信息碎片化，缺乏统一工作台 | A01店长/A02后厨/A03采购三个AI助理，按角色聚合待办和决策建议 | D2冲刺中 |

### 明确边界（PRD **v5.3i** §1.3）

- ✅ 火瞳**连接** POS、ERP、库存、采购和会员系统，**不取代**它们
- ✅ 给出预警、损耗估算和订货建议；正式采购和库存扣减**必须由授权人员确认**
- ✅ 当前优先两家自营店，不以外部收费或市场规模为当前阶段验收指标
- ✅ 当前聚焦火锅业态；未来可扩展至"火锅+"多业态

### 定位演进

```
v5.0（早期）: 通用火锅后厨AI → 面向外部SaaS → 客群/定价/扩张口径偏快
    ↓ （WorkBuddy v5.2 自有品牌修订）
v5.2: 自有连锁优先 → 两店验证 → "先服务自己，再对外输出"
    ↓ （7/27会议 + 市场调研）
v5.3i: 129项功能EARS（冻品供应链 + 岗位AI助理 + 全场景覆盖 + 连锁管控）
    ↓ （v5.3d~v5.3i 多次扩展：场景工作流+全场景覆盖+连锁管控）
v5.3i: 129项功能EARS（当前基线，2026-07-29）
```

> **关键洞察**：定位从"卖出去"（SaaS）纠正为"先用好"（自有验证），是PRD v5.2-v5.3最关键的修正。v5.0旧口径的"客户数""定价""扩张"等外部指标已被v5.3的三阶段路线和Go/No-Go门控替代。

## 2. 双引擎架构

### 2.1 架构全景

```
┌─────────────────────────────────────────────────────────────┐
│                     火瞳 双引擎架构                           │
├───────────────────────┬─────────────────────────────────────┤
│   视觉引擎（边缘）     │     数据引擎（云端）                  │
│   Jetson 盒子部署      │     Hub :8098 + Dashboard :3000      │
├───────────────────────┼─────────────────────────────────────┤
│ YOLO → CLIP → VLM    │  N01 销量预测（四级降级链）           │
│ 7段可插拔管线          │  N02 智能订货（EOQ/报童/安全库存）    │
│ plan_b(40ms)/plan_a   │  N03 库存台账（水位+FIFO+临期）       │
│ 场景：后厨/前厅/SOP    │  N04 损耗分析（SKU级根因诊断）        │
│      /收货/员工/食安    │  N05 供应商评分卡                    │
│                        │  N06 ERP双向连接                      │
├───────────────────────┴─────────────────────────────────────┤
│         双引擎融合闭环：视觉事件 → 库存扣减 → 损耗分析          │
│                       → 预测校准 → 订货建议 → 回灌训练          │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 融合程度评估

| 融合维度 | 状态 | 证据 |
|----------|:----:|------|
| 视觉废料 → 损耗金额 | ✅ 代码基础 | N04 LossAnalyzer（537行）接收视觉检测事件，映射SKU单价生成损耗金额 |
| 视觉废料 → 库存扣减 | ✅ 代码基础 | N04通过事件订阅自动扣减库存台账（loss_analyzer.py L17-18注释标明数据来源含"视觉检测事件"） |
| 损耗数据 → 预测校准 | 🟡 设计已就绪 | N17回灌训练设计完成，但代码尚未实现（P2，展会后开发） |
| 预测 → 订货 → 供应商评分 | ✅ 代码基础 | N01→N02→N05链路已设计，N02供应商分配按N05评分卡加权 |
| POS per-SKU → 预测引擎 | ✅ Sprint 0 Go | `pos_bridge.fetch_sku_sales()` 已实现，椒江店回测MAPE 10.6% |
| IoT 温控 → 冻品追溯 | 🔴 待开发 | S04冻品温控追溯为P2（展会后） |
| 全链路闭环跑通 | 🟡 部分 | 椒江店MAPE 10.6% + 玉环店损耗闭环7/7通过，但预测→订货→回灌完整链路未端到端验证 |

> **评价**：双引擎闭环的**设计**已经完整（PRD v5.3i §4.1有完整的7步闭环图），**骨架代码**已就位（data_engine **3566行**(2026-07-29修正)），**两个关键节点已通过Sprint 0验证**（椒江预测MAPE 10.6% + 玉环损耗闭环Pass）。但**全链路自动化**（预测→执行→偏差→回灌→更准预测）要等到展会后N17开发。

### 2.3 双引擎协同闭环（PRD v5.3i §4.1）

```
视觉引擎                         数据引擎
摄像头检测 ── 废料事件 ──→    库存扣减
 3盘毛肚废弃                     42→39盘
                                  ↓
                              损耗分析（损耗率6%，根因:过量）
                                  ↓
                              预测校准（明日↓3盘）
                                  ↓
                              订货建议（补3盘，供应商A）← N05评分卡加权
                                  ↓
                              ERP待办 ← 只建议不下单，店长确认
                                  ↓
                              实际消耗 vs 预测
                                  ↓
                              N17 回灌训练 → 下次预测更准
```

```
│ 员工 (staff_behavior/): 着装+服务响应+微笑                     │
│ IoT (iot_food_safety/): 传感器驱动+流处理+规则引擎            │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 核心设计模式

| 模式 | 用途 | 实现 |
|------|------|------|
| **可插拔管线** | 后厨推理7段独立注册，丢文件即可扩展 | `edge/kitchen/inference/stages/` 下各stage独立文件 |
| **双模式策略** | 前厅推理plan_b（40ms轻量）vs plan_a（190ms语义） | `strategies/plan_b.py` + `plan_a.py` |
| **四级降级链** | 预测引擎 L1规则→L2 SARIMA→L3 LightGBM→L4 LLM，任一层失败优雅降级 | `algorithms/baseline.py`(293行) + L1-L4独立类 |
| **Callback/Hook** | 数据引擎解耦DB实现 | SalesPredictor注入 `data_loader`/`sku_lister` 回调 |
| **EventStore** | 事件溯源+审计追溯 | Hub EventStore模式，关键操作留痕 |
| **模块化配置下发** | 平台→Hub→设备三级配置热加载 | `PUT /v1/devices/{id}/config` → heartbeat推送 |
| **多租户隔离** | 门店→区域→大区三级数据隔离 | RBAC+per-store schema |

### 5.3 数据流

```
POS系统 ──per-SKU销量──→ pos_bridge ──→ sales_daily 表 ──→ N01预测
ERP系统 ──PO+收货─────→ erp_bridge ──→ inventory 表 ──→ N03库存
视觉AI ──废料事件─────→ event pipeline ──→ N04损耗分析
IoT传感 ──温/湿/重─────→ iot_readings ──→ K19-K22告警
外部数据 ──天气/节假日─→ ext_data ──→ FeatureStore
                                    ↓
                            N02 订货建议 → ERP待办（人工确认后才下单）
```
