## 1. 概述

### 1.1 什么是用户故事映射

用户故事映射是一种敏捷需求技术，用于：
- 从用户视角描述系统功能
- 确保需求覆盖完整
- 建立需求→设计→代码的可追溯链路

### 1.2 本文档结构

```
角色 (Who)
  └─ Epic (大目标)
       └─ User Story (具体需求)
            ├─ 验收标准 (Acceptance Criteria)
            ├─ 对应PRD功能点
            └─ 实现状态
```

## 2. 角色一：店长

### 2.1 角色画像

| 属性 | 描述 |
|------|------|
| **姓名** | 张店长（示例） |
| **职责** | 负责门店整体运营、成本控制、人员管理 |
| **痛点** | 损耗难追踪、采购价格不透明、库存不准 |
| **目标** | 单店年省≥¥15万，提升运营效率 |

### 2.2 Epic 1: 运营数据看板

**Epic 目标**: 一目了然掌握门店运营全貌

#### Story 1.1: 查看实时损耗概览

```gherkin
As a 店长,
I want to see a real-time waste overview dashboard,
So that I can identify loss hotspots and take timely action.

**验收标准 (AC)**:
- AC-1.1: Dashboard 显示今日/本周/本月损耗金额和率
- AC-1.2: 支持按品类（荤菜/素菜/锅底）筛选损耗数据
- AC-1.3: 损耗异常值高亮显示（超过阈值标红）
- AC-1.4: 数据刷新延迟 ≤5分钟

**对应PRD**: L200-L220 (数字座舱 - 损耗监控)
**实现状态**: ✅ 基础版完成 (D2-S04 数字座舱)
**关联模块**: `hotpot_platform/cloud/cockpit/`
```

#### Story 1.2: 查看销量趋势图

```gherkin
As a 店长,
I want to view sales trend charts (daily/weekly/monthly),
So that I can forecast demand and optimize procurement.

**验收标准 (AC)**:
- AC-2.1: 支持日/周/月三种时间维度切换
- AC-2.2: 图表支持 hover 显示详细数值
- AC-2.3: 可叠加去年同期对比线
- AC-2.4: 支持导出PNG/PDF报告

**对应PRD**: L230-L245 (数字座舱 - 销量分析)
**实现状态**: 🔄 部分完成 (Dashboard框架就绪，数据接入待深化)
**关联模块**: `hotpot_platform/dashboard/` + `cloud_mock.js`
```

#### Story 1.3: 查看成本构成分析

```gherkin
As a 店长,
I want to see cost breakdown by category (ingredients/labor/utilities),
So that I can identify cost reduction opportunities.

**验收标准 (AC)**:
- AC-3.1: 饼图展示各成本项占比
- AC-3.2: 支持钻取到具体SKU的成本明细
- AC-3.3: 显示同比/环比变化率

**对应PRD**: L250-L265 (数字座舱 - 成本分析)
```

### 2.3 Epic 2: 采购管理

**Epic 目标**: 规范化采购流程，降低采购成本

#### Story 2.1: 维护货品主数据

```gherkin
As a 店长,
I want to maintain a standardized product master database,
So that all procurement uses consistent SKU names and specifications.

**验收标准 (AC)**:
- AC-1.1: 支持货品CRUD操作（创建/查看/修改/删除）
- AC-1.2: SKU编码唯一且自动转大写
- AC-1.3: 支持分页列表 + 关键词搜索 + 分类筛选
- AC-1.4: 已锁定的货品关键字段不可直接修改
- AC-1.5: 支持初始化种子数据（展会演示用）

**对应PRD**: L386 EARS (S01 货品主数据管理)
**实现状态**: ✅ 完成 (D1-S01, Commit: 52b089b)
**关联模块**: `supply_chain/models.py` + `product_master_api.py` + `products.html`
**测试结果**: 10/13 API通过 ✅
```

#### Story 2.2: 创建采购订单

```gherkin
As a 店长,
I want to create purchase orders based on sales forecasts,
So that I can maintain optimal inventory levels without overstocking.

**验收标准 (AC)**:
- AC-2.1: 支持手动创建订单（选择SKU+数量）
- AC-2.2: 系统根据销量预测自动建议采购量
- AC-2.3: 订单状态机：draft → submitted → confirmed → received
- AC-2.4: 订单历史可查询和导出

**对应PRD**: L400-L420 (S03 采购订单管理)
**实现状态**: 🔲 待开发 (D1-S03)
**前置依赖**: D1-S01 货品主数据 ✅
**优先级**: P0 (8月中旬开始)
```

#### Story 2.3: 审批供应商变更申请

```gherkin
As a 店长,
I want to review and approve supplier change requests (price adjustment, brand replacement),
So that I can control procurement quality and cost.

**验收标准 (AC)**:
- AC-3.1: 变更申请列表展示（待审批/已通过/已驳回）
- AC-3.2: 支持查看变更前后对比
- AC-3.3: 一键批准/驳回 + 填写审批意见
- AC-3.4: 审批后自动更新货品主数据并记录版本

**对应PRD**: L430-L445 (S01 变更管理)
```

### 2.4 Epic 3: 损耗预警与处理

**Epic 目标**: 及时发现和处理损耗异常

#### Story 3.1: 接收损耗预警通知

```gherkin
As a 店长,
I want to receive alerts when waste exceeds threshold,
So that I can investigate and take corrective action promptly.

**验收标准 (AC)**:
- AC-1.1: 当日损耗 > ¥500 或 > 5% 时触发预警
- AC-1.2: 预警通知推送到 Dashboard 和 Edge UI
- AC-1.3: 预警信息包含：时间/品类/金额/可能原因
- AC-1.4: 支持一键跳转到详情页

**对应PRD**: L300-L315 (告警网关)
**实现状态**: 🔄 框架就绪 (`alert_gateway/`)
**优先级**: P1 (展会前实现Demo)
```

#### Story 3.2: 查看损耗根因分析

```gherkin
As a 店长,

**验收标准 (AC)**:

- AC-2.2: 关联当时的操作员和时间段
- AC-2.3: 如有视觉AI检测记录，提供截图证据

**对应PRD**: L320-L335 (损耗分析)
**实现状态**: 🔲 待开发
```

## 3. 角色二：厨师长（潘厨）

### 3.1 角色画像

| 属性 | 描述 |
|------|------|
| **姓名** | 潘总（潘厨） |
| **职责** | 后厨品质管控、食材质检、供应商质量评估 |
| **痛点** | 供应商送货品质不稳定、人工质检效率低 |
| **目标** | 确保食材品质100%合格，建立可追溯的质量体系 |
| **使用场景** | 每日收货质检、每周供应商评分、每月品质复盘 |

### 3.2 Epic 4: 收货品质管控

**Epic 目标**: 确保每次收货的品质符合标准

#### Story 4.1: 执行收货质检

```gherkin
As a 厨师长,
I want to perform quality inspection on incoming goods with VLM assistance,
So that I can efficiently detect quality issues and reject substandard items.

**验收标准 (AC)**:
- AC-1.1: 扫描/选择SKU后显示该货品的标准图片和信息
- AC-1.2: 拍照上传后VLM自动比对（外观/颜色/形状）
- AC-1.3: VLM返回质检结果（A/B/C/D等级）+ 置信度
- AC-1.4: 支持人工修正VLM判断结果
- AC-1.5: 质检结果自动关联到收货记录

**对应PRD**: L450-L480 (S02 收货质检 + VLM)
**实现状态**: 🔲 待开发 (D1-S02)
**关键技术**: VLM Bridge → Jetson推理 → 结果返回Edge UI
**优先级**: P0 (8月第一周开始)
```

#### Story 4.2: 审批品质异常

```gherkin
As a 厨师长,
I want to review and approve/reject quality exceptions,
So that I can maintain quality standards while being fair to suppliers.

**验收标准 (AC)**:
- AC-2.1: 异常收货列表（VLM判定为C/D级）
- AC-2.2: 查看照片证据 + VLM分析详情
- AC-2.3: 支持"拒收"/"有条件接收"+ 填写原因
- AC-2.4: 审批结果通知供应商和店长

**对应PRD**: L485-L500 (S02 审批流程)
**实现状态**: 🔲 待开发 (D1-S02)
**关键角色**: 潘厨 = 品质最终决策者
```

#### Story 4.3: 评估供应商质量

```gherkin
As a 厨师长,
I want to view supplier quality scores and rankings,
So that I can make informed decisions about supplier relationships.

**验收标准 (AC)**:
- AC-3.1: 供应商评分卡（准时率/拒收率/平均偏差/综合分）
- AC-3.2: 月度趋势图（评分变化）
- AC-3.3: 支持按品类筛选供应商表现
- AC-3.4: 不达标供应商自动标记预警

**对应PRD**: L520-L535 (S04 供应商协同)
**实现状态**: 🔲 待开发 (D1-S04)
**依赖**: S02 质检数据积累 (至少2周)
```

| **使用场景** | 巡店记录、周报生成、跨店对比分析 |

### 4.2 Epic 6: 多店数据对比

**Epic 目标**: 快速识别各店运营差异

#### Story 6.1: 对比多店核心指标

```gherkin
As a 督导,

So that I can identify best practices and underperforming stores.

**验收标准 (AC)**:
- AC-1.1: 选择多家店后展示指标对比表
- AC-1.2: 支持排序（升序/降序）找出最好/最差
- AC-1.3: 高亮显示异常值（超出±2σ）
- AC-1.4: 支持导出对比报告

**对应PRD**: L600-L620 (多店分析)
**实现状态**: 🔲 待开发 (当前仅支持单店)
**前提条件**: 第二门店（玉环店）部署完成
**优先级**: P2 (阶段二：自有扩张时实现)
```

#### Story 6.2: 查看巡店问题跟踪

```gherkin
As a 督导,

So that I can ensure problems are actually fixed and not forgotten.

**验收标准 (AC)**:
- AC-2.1: 问题列表（问题描述/责任人/截止日期/状态）
- AC-2.2: 状态流转：open → in_progress → verified → closed
- AC-2.3: 超期未解决问题自动升级提醒
- AC-2.4: 问题解决率统计

**对应PRD**: L625-L640 (巡店管理)
**实现状态**: 🔲 待开发
**优先级**: P2 (阶段二)
```
